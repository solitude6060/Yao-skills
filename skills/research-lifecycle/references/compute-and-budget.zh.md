# 運算資源、付費 API、儲存空間與備份保存

英文版 [compute-and-budget.md](compute-and-budget.md) 為執行規範。

運算資源、經費與磁碟空間都是研究中需要排程的資源。每批實驗的預算（吞吐量、成本類別、低成本試跑層）在 `experiment-planning` 規劃；啟動、等待與 watchdog（監看程式）的做法在 `experiment-contract`（[execution-integrity.zh.md](../../experiment-contract/references/execution-integrity.zh.md)）。本檔記錄專案層級的規則。

## 加速器

- 有已授權的工作在排隊時，加速器（accelerator：GPU 等運算裝置）不閒置。無人看管的時段（夜間、長時間會議）開始之前，先排好下一批已授權的工作並設好 watchdog。watchdog 每次結束時都找出根本原因並修正；跳過該工作只會讓原因繼續存在。
- 裝置記憶體允許時平行執行工作。每個工作宣告它需要的記憶體。主機有共用的裝置鎖（device lock）時，以共用模式持有（需要整張裝置的模型伺服器以獨占模式持有）；沒有時，每次啟動前檢查整張裝置的可用記憶體。
- 承諾完成日期之前，先用量測到的吞吐量（真實設定的短時間執行）估計執行時間。
- 依決策價值排列佇列：結果可能讓其他執行變得不必要的工作排第一。

通用案例：兩個佇列在夜間閒置了好幾個小時，原因是重新啟動時遇到檔案權限錯誤，而啟動檢查比對到它自己的指令列；另一例是一個等待程式在等一個已結束但尚未被回收（unreaped）的行程，浪費了大半個晚上。

## 共用或借用的硬體

| 規則 | 防止的失誤 |
|---|---|
| 與出借者約定權重、環境、快取與輸出放在哪裡；大型檔案不寫到其他位置 | 塞滿出借者的系統磁碟 |
| 記憶體上限以「整張裝置的使用量減去啟動前的基準值」計算，並限制伺服器本身（記憶體配置器或使用率上限） | 以單一行程為對象的防護從未觸發，因為容器不回報單一行程的記憶體 |
| 長時間滿載之前，先通知擁有者 | 出借者在同一裝置上的工作遇到電力或記憶體問題 |
| 每次執行前檢查可用記憶體與其他使用者的行程；絕不碰其他專案的行程 | 讓別人的工作當掉 |
| 刪除腳本先證明自己在哪台主機上執行 | 在與借用副本使用相同路徑的主機上刪掉原始檔 |

通用案例：一個模型伺服器在借用的裝置上短暫超過約定的記憶體上限，因為防護讀取的是單一行程的記憶體，而容器把這個值回報為無法取得。

## 付費 API

1. 每次執行前，用同一種請求形式量到的費率，估計 token（模型計算輸入長度的單位）數與費用，並與剩餘餘額比較。
2. 維護帳本（ledger）：執行、日期、請求數、輸入與輸出 token、估計費用、實際扣款、餘額，並設單次執行上限與累計上限。花費之前先寫紀錄，事後與服務提供者的紀錄核對。
3. 只執行完整的儲存格（cell：實驗矩陣中的一格）。估計費用超過剩餘餘額的儲存格不啟動；要超過餘額之前先問擁有者。
4. 固定模型版本，並記錄服務在每個回應中回傳的版本或模型識別碼。改用較新版本由擁有者決定，並以一次小規模的配對檢查佐證。
5. 依類別記錄成本：前置準備、選參、推論、重試、更新（refresh）。每次請求的成本主張不含一次性的前置準備，並寫明更新多久發生一次。

通用案例：執行計畫所依據的餘額只比估計費用略高；另一例是服務提供者釋出較新版本時，擁有者保留較早的版本，讓結果維持可比較。

## 儲存空間管理

- 保留每個設定選出的 checkpoint（模型檢查點），以及已收錄執行的逐單位原始分數。
- 網格中每個設定的 checkpoint，以及每個 epoch（訓練輪次）存下的原始分數，在選參結果已記錄且沒有程式讀取它們之後，移到永久封存儲存區（依下方的保存規則）；移動前先檢查有沒有讀取者。
- 每批實驗前檢查可用空間；磁碟滿了會讓主機上的每個佇列停下。

通用案例：一個有閉式解（closed-form）模型的逐設定 checkpoint，加上以文字格式存下的逐 epoch 原始分數，塞滿了磁碟，佇列因此停止。

## 備份保存

1. 清理、替換 checkout（工作目錄中簽出的檔案）或退役之前先備份：受版本控制、未受版本控制與被忽略的檔案、環境，以及 symlink（符號連結）指向的目標（複製連結本身不會保存它的目標）。
2. 每個單位寫一個封存檔，附逐檔 checksum（校驗碼）清單；每個封存檔都從目的地讀回來驗證。
3. 備份過程中發生任何網路或儲存錯誤之後，重新驗證錯誤前後寫入的每個封存檔。
4. 每個單位都驗證通過、且擁有者確認清單之後，才刪除本機檔案。工作副本依 `worktree-hygiene` 記錄的關卡退役。
5. 私人備份保持私密且永久；還原說明記在清單旁邊。

通用案例：一次寫到網路共用資料夾的備份，在連線錯誤後停滯了很長一段時間，必須接續執行；另一例是有一個封存檔直到讀回驗證時才發現已損壞。
