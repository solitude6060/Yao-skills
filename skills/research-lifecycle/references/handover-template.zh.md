# 交接文件與新題目起始文件

英文版 [handover-template.md](handover-template.md) 為執行規範。

有兩份文件帶著專案跨越邊界：session（工作階段）交接文件（同一專案的下一個 session），以及新題目起始文件（在新的 repository 或 session 中進行的後續研究）。兩者都存放在永久的專案檔案中；對話摘要不算交接。

## Session 交接

使用 `context-hygiene` 的通用範本，並加上下列研究欄位：

| 欄位 | 內容 |
|---|---|
| 執行中的工作 | 指令、pid file（記錄行程編號的檔案）、紀錄檔路徑、代表完成的結尾行、依量測吞吐量估計的完成時間 |
| 證據狀態 | 每個未結的結果：planned 已規劃、running 執行中、executed 已執行、verified 已驗證、admitted 已收錄或 superseded 已被取代 |
| 待擁有者決定的事項 | 白話名稱、選項、建議、哪些工作在等它 |
| 最後一次收錄的狀態 | 結果表的 commit、報告的 commit、已發布頁面的 commit |
| 接續步驟 | 第一個指令，以及接下來的具體動作 |
| 已知陷阱 | 不能修改的執行中腳本、正在被讀取的輸入、shell 的特殊行為、目前有效的資源限制 |

## 新題目起始文件

後續題目從一份文件開始。新的 session 先讀這份文件，應該不必重新推導任何決定就能開始工作。

| 章節 | 內容 |
|---|---|
| 0. 與先前文件的關係 | 表格：文件、題目、關係（沿用、被取代、僅供背景） |
| 1. 閱讀順序 | 表格：順序、文件與章節、目的 |
| 2. 位置 | Repository 與實驗輸出的位置，以 `realpath` 解析，且不在暫存儲存區 |
| 3. 第一批指令 | `date`；重現本題目所依據的沿用數字，並與存檔的輸出做 diff（比對差異）；只查詢資源狀態；檢查憑證是否存在，但絕不印出它的值 |
| 4. 沿用的規則與差異 | 從前一個協定保留什麼、改了什麼、為什麼。重新檢查每個沿用的限制：只有新問題需要時，它才約束新題目 |
| 5. 沿用的資產 | 資料、使用者群與其曝光紀錄、附身分的 checkpoint（模型檢查點）、固定 commit 的程式 |
| 6. 已決定的事項 | 擁有者的決定，照原文並註明日期：投稿會議順序、資源限制、位置、證據階段、可放進外部請求的資料 |
| 7. 先問的問題 | 自成一體、附建議的問題（見 owner-communication.zh.md） |
| 8. 第一批工作項目 | 要建立的紀錄、先寫的測試、第 0 階段的重現、第一個初步研究階段 |
| 9. 開場提示詞 | 可直接貼給新 session 的文字（範本如下） |

### 開場提示詞範本

```text
這是 <專案> 的第一個 session。題目：<一句話，依方法實際做的事來稱呼它>。

1. 依序先讀：<起始文件第 0 到 8 節>；<沿用的規則檔>；<可行性紀錄>。
2. 擁有者已決定（附日期）：<投稿會議順序>；<資源限制>；<位置>；<seed 與證據階段>；
   <可放進外部請求的資料>。
3. 先問擁有者（自成一體，附建議）：<待決事項>。
4. 第一批工作：<建立紀錄>；<先寫的測試>；<第 0 階段的重現>；<第一個初步研究階段>。
5. 規則：<繼續或停止條件只讀驗證資料>；<資訊邊界>；<執行失敗與方法失敗的區分>；<成本欄位>；
   <驗證者的檢查頻率>；<擁有者的指令照原文記錄，時間取自 date>；<前一個專案的產出物保持凍結>；
   <外部請求不含個人資料>；<對話語言與寫作規則>。
```

通用案例：一份後續研究的協定草稿把模型訓練當成例外，因為先前的研究不需訓練（training-free），但新問題其實需要訓練；另一例是擁有者問另一份協定草稿為什麼與先前研究不同，於是它被改寫成「先前的協定加上一份差異清單」。

## 論文範圍縮小時的封存完整性

從論文中移除某個資料集、基線或分析時，它在結果表中的列、它的紀錄、頁面與原始產出物都保留。把只屬於論文的檔案移到專案的封存資料夾並記錄原因；實驗封存保持完整且可重現。

通用案例：一個不完整的基線從稿件中移除，它的結果列與產出物仍留在結果表與實驗紀錄中。
