# 引用三步檢查

英文版 [citation-ladder.md](citation-ladder.md) 為執行規範。

審稿人只要發現一則引用把來源沒有的內容歸給它，就不再信任其他每一則引用。因此每筆參考文獻都要爬三步，只有第三步能讓它進入論文。

## 三個步驟

| 步驟 | 檢查 | 記錄的證據 | 常見失誤 |
|---|---|---|---|
| 1. 存在 | 解析識別碼（DOI、arXiv id、會議論文集頁面） | 解析結果與檢查日期 | 捏造或打錯的參考文獻 |
| 2. 書目資料正確 | 與解析結果或出版者頁面比對作者、標題、會議或期刊、年份、頁碼 | 更正後的條目 | 年份、會議或作者名單錯誤；正式版本已出版，卻仍引用 preprint（預印本） |
| 3. 主張確實存在 | 在來源全文中找到被引用的主張 | 一小段引文，附章節與頁碼 | 來源沒有說句子歸給它的內容；把來源沒有使用的術語歸給它 |

停在第 1 或第 2 步的參考文獻可以放在閱讀清單。在論文中，引用它的句子要嘛達到第 3 步，要嘛拿掉這則引用。

## 每則引用的紀錄

```markdown
| Key | 論文中的句子（位置） | 達到的步驟 | 來源中的引文與位置 | 修正 |
|---|---|---|---|---|
```

## 方法元件的概念來源

方法的某個元件被寫成「新的」之前，先在先前研究中尋找相同的原理（同一個估計量、加權方式、內插或分解，只是名稱不同）。把找到的作品當作概念來源引用，並寫明差異。找不到概念來源的元件，寫成設計選擇並附理由。

通用案例：一種加權方式原本是本地自行發明的，直到擁有者問它的概念來源，才改為引用一個使用相同原理的既有方法；另一例是把某個知名方法沒有使用的術語歸給它。

## 投稿前檢查

- 檢查參考文獻列表中的每一筆，不只新加的。
- 在全新的上下文中，由沒有寫這些引用句的人執行。
- 記錄更正；自動產生的參考文獻列表從它的來源重新產生，絕不手動修改。
- 送給解析服務的查詢不含個人資料：polite-pool（禮貌池：API 給附上聯絡資訊者的優先通道）參數不放 email，header（請求標頭）不放姓名或 token（存取權杖），即使 API 慣例建議這麼做。

通用案例：一條參考文獻查證的工作線，把擁有者的 email 放進書目 API 的 polite-pool 參數；上面這條規則現在寫進每一張會查詢外部服務的任務卡。
