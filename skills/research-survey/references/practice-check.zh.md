# 實務對照

英文版 [practice-check.md](practice-check.md) 為執行規範。

實務對照（practice check）只回答一個問題：對某個協定或設計選擇，官方實作與最強的基線實際怎麼做？它用先例取代自己發明的設定，或在審稿人發現之前，先把與先例不同之處寫明。

## 何時必須做

- 某個設定即將在沒有引用先例的情況下選定（切分、目標規則、同分排序、驗證抽樣、選參與重新擬合、重試、篩選條件）。
- 從規格、先前專案或其他論文沿用的設定會決定結論。
- 審稿人或指導教授問「別人是這樣做的嗎？」。
- 擁有者問了一個證據能回答的設計問題；用實務對照回答，並附建議。

## 範本

```markdown
## 實務對照：<一行寫出要做的決定>

決定與選項：<要做的選擇與替代方案>
服務的研究問題：<研究問題代號與白話名稱>

| 來源 | 類型 | 版本 | 位置 | 做法 |
|---|---|---|---|---|
| <官方實作> | 官方程式 | <commit 或 tag> | <file:line> | <行為> |
| <強基線或函式庫> | 函式庫程式 | <版本> | <file:line> | <行為> |
| <論文> | 論文內文 | <版本> | <章節、頁碼> | <寫明的設定> |

一致性：<全部一致 | 有分歧，附原因>
建議：<設定>，先例 <來源>
與先例的差異：<無 | 差在哪裡、為什麼、在哪裡揭露>
「沒有」的標示：<not found 找過沒找到／not disclosed 來源沒寫／inferred absent 推論沒有／verified absent 確認沒有，必要時逐一來源標示>
快取：<程式版本與 PDF 存放的位置>
```

讀實際執行該設定的程式路徑（訓練或評估的進入點，以及它呼叫的函式），不只讀 README 或設定檔的預設值。設定檔中的預設值可能與已釋出 checkpoint（模型檢查點）實際使用的值不同；記錄主張依據的是哪一個。

## 通用例子

| 決定 | 去哪裡找 | 記錄什麼 |
|---|---|---|
| 切分與目標規則（哪個事件是測試目標，哪個用於驗證） | 每個官方實作的評估資料載入程式；論文的協定章節 | 每位使用者的目標索引、驗證資料如何形成、切分是逐人還是全域 |
| 時間戳相同的事件如何排序 | 前處理程式；資料集文件中關於時間戳解析度的說明 | 依序列出排序鍵（時間戳，再來是原始列順序，或商品識別碼）；時間戳的解析度 |
| 大型資料集上的驗證抽樣 | 官方程式的驗證迴圈 | 驗證全部使用者或抽樣、樣本數規則、seed（隨機種子）、被評估的使用者是否在樣本內 |
| 選參時的 checkpoint 與重新擬合 | 訓練迴圈與報告腳本 | 回報的模型是驗證最佳的 checkpoint，還是用訓練加驗證資料重新擬合（refit）的模型 |
| 生成式基線的重試輪數 | 該基線的推論腳本與論文 | 無效輸出是否重新生成、幾輪、輪與輪之間解析器是否改變 |
| 資料集篩選條件（最少互動數、沒有文字的商品） | 官方的前處理腳本 | 篩選順序、門檻、篩選後的數量與已發表統計的比較 |

通用案例：在一次記錄下來的對照中，某個序列推薦模型的官方程式與一個廣泛使用的函式庫，都回報驗證最佳的 checkpoint 而不重新擬合；這解決了一個已經產生許多被取代結果列的重新擬合問題。另一例是在逐使用者 leave-one-out 下，一個驗證樣本在抽取時排除了被評估的使用者，必須重抽，讓樣本包含他們（使用者互斥協定下則要排除他們）。

## 規則

- 實務對照引用固定版本的程式；部落格文章、摘要整理或 agent（代理程式）的描述，只是通往該程式的線索。
- 先例互相矛盾時，逐一記錄並寫明原因；選擇符合研究問題的那一個，並揭露這個選擇。
- 與先例不同的做法，在執行前就於協定中決定，並寫入決策紀錄。
- 會改變執行中協定的實務對照，觸發 `experiment-contract` 的重跑清單。
