# 解釋這個數字

英文 [SKILL.md](SKILL.md) 是執行規範。效能數字的七個問題在 `references/benchmark-checklist.zh.md`。
改編自 Lauren Tan 的 pstack `principle-explain-the-number` 與 `benchmark-checklist`
（MIT，`cursor/plugins` 的 `1ba91fc`，見 `LICENSE`）。

用在量測之前，以及相信、回報或根據一個量到的數字做決定之前：加速比、效能退步、吞吐量、
延遲、benchmark 或評估指標。數字要能說出「被什麼限制住」和「為什麼不是量到別的東西」，
才算結果。

## 跑之前

- 先寫下預計要報告的那一句話，以及會改變決定的結果，寫成相對於某個具名比較對象的方向。只有要主張
  「沒有差異」時，才事先宣告容許範圍（margin：多小的效果就不重要）。寫明預期的雜訊範圍、比較設計
  （獨立執行，或依 seed、使用者、輸入成對）與證據階段。確認階段：在該設計下「差值」的不確定性大於預期效果時就停；篩選階段報告標明的點差值。
- 讀量測程式：它計時、計數、平均和忽略了什麼。
- 檢查機器負載：`uptime`、`nproc`，用到 GPU 時看 `nvidia-smi`。有其他工作在跑又停不掉時，
  兩邊交錯執行並註明。延遲只在同一裝置上比較；裝置不同時，在同一裝置上重新量測雙方。

## 四項義務

1. **為什麼不是兩倍？** 效能數字：用 profile 或執行中的系統計數器，找出限制結果的資源或
   程式路徑（核心、鎖、記憶體頻寬、磁碟、網路、GPU、data loader、壓測端），再對回原始碼；
   讀程式碼猜的不算；說不出為什麼不是兩倍，就還不知道自己量到什麼。評估指標：改問是什麼限制了分數，例如資料涵蓋範圍（訓練中沒出現的
   item）、該協定下指標的上限、候選集大小、標註雜訊或協定本身。
   機制還沒查明時，量測結果與未解釋的上限分開陳述。
2. **列出這個數字還可能在量什麼，逐一用證據排除**：錯誤或跳過的工作、快取、沒執行到的
   程式、沒調校的一方、雜訊、端到端占比太小的元件。評估指標另外查：split 之間的
   leakage（資料洩漏）、兩邊候選集或指標定義不同、baseline 用預設值、只跑一個 seed、
   有跑但沒做完任務的執行、差距只出現在單一模型或資料集（若是如此就要寫明），並問這個
   情境是否重要。
3. **證明可重現**：效能至少每邊五次交錯執行，報中位數與範圍。評估指標分兩個證據階段。
   screening（篩選階段）：跑一次，報點估計或成對差值，不報區間；可以用來決定下一個實驗，
   但不能支撐穩健性或優越性的主張。confirmatory（確認階段，用於最終主張）：報共同測試單位上
   成對差值的不確定性（例如逐使用者的 bootstrap 自助抽樣）；有訓練或解碼隨機性的方法，另外跑多個
   seed 或重複執行，否則主張要寫明只根據一次訓練執行。用「差值本身」的不確定性判斷，不要只看各邊
   自己的變異。只有差值的整個區間
   都落在跑之前宣告的容許範圍內，才回報「無可量測差異」；區間包含 0、但沒有整個落在容許範圍內時，
   回報「結論待定」，也就是「在此樣本數下差異不顯著」。確定性（determinism）要在註明的執行環境下實際觀察到，
   不能假設。
4. **證據跟著數字走**：記錄數字取自哪一個確切的結果列（方法、設定、使用者群組、篩選條件；
   取已收錄的那一列，不取多列中最好的一列），以及次數、變異、限制因素、指令、commit、資料版本。

效能數字回答 `references/benchmark-checklist.zh.md` 的七個問題；推薦系統指標另外套用
`recsys-evaluation`；要支撐主張的數字，另外要通過專案的結果收錄檢查（`experiment-contract`）。

## 回報

先講結論：較快、較慢、較好、較差、無可量測差異或結論待定；screening 結果要註明只跑一次。
數字附單位、次數、範圍與限制因素。有一方沒調校或沒算錯誤數，就寫「結論待定」；效能結論另外在限制因素
說不出來或無法確認工作有執行時寫「結論待定」；評估結論另外在兩邊協定不同、有執行沒做完，或確認階段的
主張沒有差值的不確定性時寫「結論待定」。都要指出缺口。

粗估或 screening 的單次執行，仍要確認沒出錯、工作有執行；結果看起來不對，就做完整檢查。

## 跳過這一步的徵兆

- 開跑之前沒有寫下「會改變決定的結果」。
- 回報的數字沒有執行次數，或主張缺少其證據階段要求的不確定性；效能數字沒有指出限制因素；評估數字既沒有
  指出分數的上限來源，也沒有說明上限尚未解釋。
- 省下的時間超過被修改部分原本花的時間，或指標增益超過被修改元件能影響的範圍。

與 `first-principles` 的分工：`first-principles` 在動手前重新推導一個假設；本 skill 在相信一個量測之前先檢驗它。
