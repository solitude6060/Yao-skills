# Benchmark 檢查清單

英文 [benchmark-checklist.md](benchmark-checklist.md) 是執行規範。改編自 Lauren Tan 的 pstack
`benchmark-checklist`（MIT，`cursor/plugins` 的 `1ba91fc`）。每個問題都用一次實際執行的證據回答，
不要用讀程式碼得到的猜測回答。

1. **為什麼不是兩倍？** 指出限制因素（limiter）。在一次不拿來回報的執行裡做 profile（效能剖析），
   因為 profiler 與 tracer 會拖慢工作。看每個行程的 CPU（`top`、`pidstat`）、執行期 profiler
   （`py-spy`、`perf`、`nsys`、`node --cpu-prof`）、I/O 等待與系統呼叫次數（`strace -c`），再把熱點對應回
   原始碼。注意負載產生器：它若先飽和，量到的就是負載產生器。某個修改沒有讓數字變動時，限制因素會說明
   原因；先找出它，再判斷這個修改沒用。
2. **有沒有調校？** 每一方都用實際運作的方式執行：release 或最佳化建置、正式環境的旗標與環境設定、
   批次與交易設定、執行緒與連線池大小、與實際使用相同冷熱程度的快取、相同版本與資料、相同裝置（不同裝置
   量到的延遲不互相比較；在同一裝置上重新量測雙方）。有一方用預設值時，比較的是設定，不是實作。限制因素
   若是一項設定（每列 commit 一次、debug 建置、缺少索引、沒設定 `OMP_NUM_THREADS`），代表那一方沒有調校；
   先調校再量一次，才選出勝者。無法調校時，不要從那次執行選勝者。使用者要決定採用哪個選項時，把主張縮小成
   「目前設定下的程式」也不能解決這個問題，因為他們採用的是選項本身，不是今天的設定。
3. **有沒有超過極限？** 實際算一遍：每秒位元組數對照磁碟、記憶體與網路頻寬；每秒操作數乘以每次操作成本，
   對照核心數；省下的時間對照被修改部分原本花的時間。移除只佔執行時間 10% 的部分，整體最多快約 11%
   （Amdahl 定律）。結果超過硬體極限時，例如吞吐量高於量到的磁碟、記憶體或網路頻寬，通常量到的是別的
   東西：沒做事的操作、計時錯誤或程式錯誤。固定工作量比較下，加速比大於參與運算的處理單元數，稱為
   superlinear（超線性）；當每個 worker 的工作集開始放得進快取時，這可能是真的。回報實體核心數、硬體執行緒數
   （`nproc` 算的是邏輯 CPU）與實際使用的 worker 數，再用快取與記憶體階層計數器、每個 worker 的問題大小與
   循序執行的基準確認，之後才接受或否定這個結果。
4. **有沒有出錯？** 計算失敗與非成功回應的數量，並檢查輸出是正確的，不只是有輸出。被拒絕的請求通常很快；
   逾時與重試很慢。腳本沒有計算錯誤數時，把計數加上去。
5. **能不能重現？** 每一方至少交錯執行五次，讓暖機、延遲初始化、快取與溫度飄移不偏向任何一方。報中位數與
   範圍。差距很接近時，用 rank-sum test（秩和檢定）或量測工具本身的統計。
   評估指標要寫明證據階段。screening（篩選階段）：跑一次，報點估計或成對差值，不報區間；可以用來決定下一個
   實驗，但不能支撐穩健性或優越性的主張。confirmatory（確認階段，用於最終主張）：報共同測試單位上成對差值的
   不確定性（例如逐使用者的 bootstrap 自助抽樣）；被比較的方法有訓練或解碼隨機性時，另外跑多個 seed 或重複
   執行，否則寫明主張只根據一次訓練執行。逐單位的 bootstrap 只涵蓋單位抽樣的變異，不涵蓋 seed 的變異。
   區間包含 0 代表「在此樣本數下差異不顯著」；要主張等價，整個區間必須落在跑之前宣告的容許範圍（margin）內。
   只有在註明的執行環境下（同一個伺服器 session、裝置與軟體版本）實際觀察到重複執行結果完全相同，才稱一個
   方法是確定性的（deterministic）；在同一個 session 內重複一致的答案，跨 session 仍可能不同。
6. **重不重要？** 每個微觀結果旁邊，都量一次使用者或實驗實際等待的端到端路徑，用接近實際的資料大小與
   並行程度，並把微觀結果報成佔整體的比例。
7. **工作真的有發生嗎？** 確認工作在計時區間內執行：kernel 有啟動並同步、資料列有寫入、位元組有讀取、結果有
   被使用。延遲執行的程式（沒被消費的 generator、沒被 await 的 promise、編譯器可以丟掉的結果、沒有同步的非同步
   GPU 呼叫）會替從未發生的工作產生數字。
