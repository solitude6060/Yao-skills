# 第一原理稽核

英文 [SKILL.md](SKILL.md) 是執行規範。案例在 `references/cases.md`。

用在「這個 session 沒驗證過就要照著做」的時刻：使用者提的解法、沿用的慣例、
reviewer 的指控、子代理給的數字、好到不合理的結果，以及任何「降門檻、跳過檢查、
關掉測試、先寫死、重試就好」的念頭。

1. 五個問題直接打在回覆裡。建構類問需求、假設、是否驗證、錯了會怎樣、是否只治症狀；
   修復類問限制在保護什麼、真正目標、限制是否合理、修法是否保住性質、是繞過還是根因。
2. 每個事實主張都要有可查證的來源：URL、`file:line`、探測輸出、筆數。批次摘要、
   子代理表格、reviewer 的嚴重度都不算來源。
3. 判定為繞過時，選一條：寫 ADR 改標準、重寫測試、擴大上游輸入、或等待。
4. 緊急修補不免除審查；照專案門檻跑 `triple-review`。
5. 在 PR 說明或計畫檔留下五行稽核紀錄；出現「沿用」「未驗證」「無 ADR 的繞過」即不可合併。
6. 動手前先讀專案 `CLAUDE.md`／`AGENTS.md`、記錄查證規範的專案記憶檔、過往
   `_FIX_LOG.md`，研究專案再加 `docs/audits/` 中的相關稽核文件。
