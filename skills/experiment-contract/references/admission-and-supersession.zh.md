# 收錄與取代

英文版 [admission-and-supersession.md](admission-and-supersession.md) 為執行規範。

一個數字只有在通過這些檢查後才被收錄（admitted）。在那之前它是待定（pending），而待定的數字絕不出現在已發布的頁面或論文中。

## 收錄檢查清單

1. 完整性。每個規劃中的單位都有輸出。發生執行失敗的單位重跑到成功；仍有未解決執行失敗的執行不收錄。
2. 失敗類別。每一類分開計數：

   | 類別 | 例子 | 處理 |
   |---|---|---|
   | 執行失敗 | 記憶體不足、伺服器錯誤、當機、逾時、缺檔、連接埠衝突 | 重跑；記錄嘗試次數與原因；絕不當作結果 |
   | 超過上限的輸入 | 比模型或介面上限還長的輸入 | 先套用事先宣告的截斷（truncation）規則（先刪最舊的歷史；記錄保留的事件數與 token 數）。截斷後仍超限的輸入標為超限，計數並在分數旁回報，留在該方法的分母中、效用記 0；或所有方法都改在共同的單位上回報；絕不只對單一方法剔除 |
   | 方法失敗 | 無法解析或無效的輸出；設計上不可能產生排名 | 留在分母中、效用記 0；在分數旁回報筆數 |

3. 成本欄位。每次執行：總執行時間、每個單位的延遲（中位數與 p95）、加速器峰值記憶體、裝置。呼叫模型的執行（語言模型或 agent（代理程式）呼叫）另加每個單位的呼叫次數、平均輸入與輸出 token（模型計算輸入長度的單位）數，以及雲端代管模型的 API 費用；訓練式模型記錄在相同候選上每個單位的推論時間。缺漏的欄位盡可能從原始紀錄補齊，並寫明補齊方法；沒有這些欄位的結果列先等待。
4. 重算。依精確的列篩選條件（方法、設定、使用者群、候選數、階段），從逐單位檔案重算彙總值。回報值與重算值一致。
5. 身分。回傳的模型 id、import 的原始碼雜湊值，以及資料、候選與證據雜湊值，都與契約相符（[run-identity.zh.md](run-identity.zh.md)）。每個衍生表都要把自己每一列的 checkpoint（模型檢查點）身分與主表比對。
6. 語意。選擇目標就是契約中的目標，請求做的事與標籤相符。用另一個目標的執行是加標籤的變體。
7. 執行的選擇。收錄第一次事先登記的執行。從多次重複的測試執行中挑最好的一次，等於用測試集做選擇；重複執行以重複執行的身分回報。
8. 帳本。預算紀錄、收據與上限在花費之前就寫好，並計入每一次嘗試，包括中止的嘗試。

## 快取重用

只有在每一個科學相依項都沒有改變時，才重用快取的分數或名次：

| 相依項 | 例子 |
|---|---|
| 資料 | 版本、前處理、切分、事件對應 |
| 單位 | 使用者群、目標、候選清單 |
| 輸入 | 證據、請求的組裝方式（rendering）、prompt（提示詞）、時間邊界 |
| 模型 | 權重或回傳的模型 id |
| 程式 | 計分與解析程式的雜湊值 |
| 選參 | 選定的設定、選擇目標、重新擬合階段 |

任何一項改變，都重跑受影響的部分。用未改變的模型評估更多單位或更大的候選集合不需要重新訓練，但新輸入需要新的推論。

## 差異類別

| 類別 | 意義 | 後果 |
|---|---|---|
| 已授權的調整 | 擁有者核准的資料、評估或執行環境轉接程式（adapter） | 收錄；引用授權 |
| 分析變體 | 有效的執行，但回答的是不同或較窄的問題 | 標為 analysis-only（僅供分析）；絕不取代主結果列 |
| 執行缺陷 | 執行沒有做契約說的事 | 重跑受影響的單位 |
| 方法失敗 | 方法在設計上沒有產生有效答案 | 計入分母 |
| 未解決的差異 | 原因未查明 | 維持待定；提交擁有者 |

## 狀態標籤

| 標籤 | 可以出現的地方 |
|---|---|
| 待定（pending） | 只限內部紀錄 |
| 為某項點名主張收錄（admitted） | 結果表、頁面、論文，限於該主張 |
| 僅供分析（analysis-only） | 分析文件與附錄，需加標籤 |
| 已被取代（superseded） | 只限 exceptions（例外）封存區 |

## 取代

當協定或邊界變更，或已記錄的缺陷，使某些結果列被取代時：

1. 先執行並收錄替代結果；替代結果待定期間，被排除的列維持排除。
2. 把舊的列從現行表格移到 exceptions 封存區。絕不刪除，也絕不因分數差而封存某一列。
3. 每組結果列記錄：舊執行、替代執行、原因、原始數值、設定與產出物路徑。原始產出物移動時，保留可用的參照。
4. 有效的消融與有效的負面結果留在它們的比較中。

## 同步

一次變更同時更新：主結果表、每一個衍生投影（projection：從主表篩出的子表）、報告或分析、計畫、每一個已發布頁面（從最新已 commit 的副本重建），以及專案的 status、tracker 與 handover 紀錄。發布前把各投影的列與主表比對。

## 通用案例

- 較早時間邊界下的結果列，一直和修正後邊界下的結果列放在同一個比較中，直到它們連同原始數值被移到 exceptions 封存區。
- 三次測試執行中最好的一次被收錄，後來改回第一次事先登記的執行。
- 一個頁面顯示了尚未通過收錄的數字；擁有者要求移除。
