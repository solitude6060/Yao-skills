# 實驗契約確認

英文 [SKILL.md](SKILL.md) 是執行規範。程序與範本：[preflight](references/preflight.zh.md)（啟動前檢查）、
[execution-integrity](references/execution-integrity.zh.md)（執行完整性）、[admission-and-supersession](references/admission-and-supersession.zh.md)（收錄與取代）、[run-identity](references/run-identity.zh.md)（執行身分）。

契約（contract）是一次執行事先講定的規格：回答哪個研究問題，用哪些資料、程式、模型與讀出方式
（readout：從模型輸出取得分數或名次的方法），以及什麼算是它的結果。無效結果常來自與契約不同、
卻沒人發現的執行：同一個名稱背後換了模型、計分腳本被改過、從多次執行中挑最好的一次收錄。
在啟動前、執行中與收錄前，各比對一次契約與實際執行的內容。

## 何時使用

- 一批實驗、一次高成本重跑，或新模型、新資料集、新條件第一次執行之前。
- 佇列無人看管執行時，以及輸入、prompt（提示詞：送給模型的指令與內容）、邊界、程式或雲端模型有任何變動之後。
- 數字進入結果表、已發布頁面或論文之前。

不適用：實驗設計（[experiment-planning](../experiment-planning/SKILL.zh.md)）；重大工作完成後的獨立複查
（[research-verification](../research-verification/SKILL.zh.md)）；推薦系統的切分、候選與基線規則
（[recsys-evaluation](../recsys-evaluation/SKILL.zh.md)）。

## 1. Preflight（啟動前檢查）

1. 契約欄位。每次執行寫明：研究問題、使用者群組（cohort：開發用、報告用、校準用）、候選、輸入、
   讀出方式、seed（隨機種子）、證據階段（screening 篩選階段或 confirmatory 確認階段）、選擇目標（selection
   objective：在驗證資料上依什麼挑設定）、重試輪數、成本欄位。缺任何一欄就還不能啟動。
2. 固定身分。記錄模型版本；雲端模型記錄要求的與實際回傳的模型 id；資料集、候選與程式的雜湊值；
   執行實際 import 的每個原始碼檔的雜湊值，包括轉接程式（adapter）與計分腳本。端點別名（alias）
   不等於模型身分。
3. Smoke run（小規模試跑）。用真實設定、最大規模（最大候選集、最長輸入）、真實資料跑少數單位：
   記憶體、連接埠、解析、輸出路徑，以及成本欄位是否寫入。
4. 對等性（parity）。互相比較的模型拿到協定規定共用的輸入（比對每個單位的輸入雜湊值）；讀出方式
   依各自的原始做法，除非實驗本身控制讀出方式。
5. 重跑清單（rerun map）。輸入、prompt 或邊界有任何變動時，列出必須重跑的執行；不需重跑時寫出理由。
6. 規格經核准。高成本重跑由擁有者確認完整規格後一次啟動。不受該決定影響的部分可以先跑。

## 2. 執行中

- 執行中的腳本與它正在讀的輸入都不可變更。不要修改執行中的 shell 腳本（shell 已預先讀入後面的
  內容），也不要把檔案解壓縮到工作正在讀的輸入上。先在別處準備好變更，停下佇列，再重新啟動剩下的工作。
- 啟動時寫 pid file（行程編號檔），用它等待（`kill -0` 加上行程狀態）；不要用 `pgrep -f` 這類樣式比對
  等待，它可能比對到等待指令自己。zombie（殭屍行程：已結束但尚未被回收）代表工作已結束。
- 佇列無人看管之前，先設好 watchdog（監看程式）：加速器閒置且沒有佇列行程、某一步比預期短很多、
  非零結束碼、同一個失敗重複出現時就觸發。每次觸發都修正原因。
- 重試次數事先宣告且有上限；用完就停下診斷。不要為了讓佇列繼續而跳過不一致。
- 進度依實際輸出與行程狀態回報，不依啟動指令的結束碼。

## 3. 收錄：結果進表之前

| 檢查 | 規則 |
|---|---|
| 失敗 | 執行失敗（記憶體不足、伺服器錯誤、當機、逾時、缺檔、連接埠衝突）重跑到成功為止，記錄次數與原因，絕不當作結果回報。方法失敗（輸出無效、設計上無法排序）留在分母（denominator）、效用記 0，並另列筆數。輸入超過模型上限時：先套用事先宣告的截斷（truncation）規則；截斷後仍超限的單位另列筆數，並留在分母、效用記 0，或所有方法都改在共同的單位上報告；絕不只對單一方法剔除。 |
| 成本 | 總執行時間、延遲中位數與 p95、峰值記憶體、裝置；呼叫模型的執行另填呼叫次數、token（模型計算輸入長度的單位）數、API 費用；訓練式模型記錄每個單位的推論時間。 |
| 重算 | 彙總值由逐單位檔案依精確的列篩選條件重算。 |
| 身分 | 回傳的模型 id、原始碼雜湊值，以及每個衍生列的 checkpoint（模型檢查點）都與主表一致。 |
| 語意 | 選擇目標與請求的實際語意，和契約及標籤一致。 |
| 執行的選擇 | 收錄第一次事先登記的執行；在多次測試執行中挑選等於用測試集做選擇。 |
| 快取重用 | 只有在所有科學相依項（資料、切分、候選、輸入、模型、程式、選擇設定）都沒變時才可重用快取（cache）。 |
| 紀錄 | 帳本在花費前寫好；每次嘗試都計入。 |

契約與實際執行的每一項差異都要分類：已授權的調整（收錄，記錄授權依據）、分析變體（標為
analysis-only 僅供分析，不取代主結果列）、執行缺陷（重跑受影響的單位）、方法失敗（留在分母，回報筆數）、
未解決的差異（維持 pending 待定，提交擁有者）。

狀態標籤：pending（待定）、admitted（已收錄，註明支撐哪一項主張）、analysis-only（僅供分析）、
superseded（已被取代）。待定的數字絕不出現在頁面或論文中。協定或邊界變更要明確取代舊列：把它們移到
exceptions（例外）封存區，附上原因、替代結果與原始數值；絕不刪除。同一次變更要一起同步結果表、
它的各個衍生表、報告、計畫、已發布頁面與專案紀錄。

## 輸出

在執行目錄旁寫下 preflight 紀錄與收錄紀錄，每個被取代的列寫一筆 exceptions 紀錄。用專案的對話語言
向擁有者回報，每次執行一行：狀態與尚未解決的差異。已收錄的列接著交給
[research-verification](../research-verification/SKILL.zh.md)。
