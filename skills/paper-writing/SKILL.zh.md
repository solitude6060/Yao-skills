# 論文寫作：正文、表格、附錄

英文 [SKILL.md](SKILL.md) 是執行規範。附範例的寫作規則在 [references/writing-rules.zh.md](references/writing-rules.zh.md)。表格與圖的規則在 [references/tables-and-figures.zh.md](references/tables-and-figures.zh.md)。正文與附錄的分工在 [references/body-appendix.zh.md](references/body-appendix.zh.md)。十二篇範本論文整理出的各章節篇幅與寫法在 [references/section-patterns.zh.md](references/section-patterns.zh.md)。

審稿人依正文判斷；許多會議告知審稿人，不需要閱讀頁數上限之後的內容。正文的每一句話只做四件事之一：提出問題、說明如何檢驗、報告觀察到的結果、說明結果的意義。其他內容刪除，或移到附錄（appendix）。

## 何時使用

- 草稿超過頁數上限、文字冗長，或讀起來像實驗紀錄。
- 表格重複同一組數字、附註很長，或一張表同時回答好幾個問題。
- 資料集、模型或結果有變動，文字必須跟著更新。
- 草稿送給指導教授、共同作者或投稿系統之前。

不適用：建立論證本身，請用 `paper-argument`；實驗協議是否有效，請用 `recsys-evaluation`；檢查沿用下來的假設，請用 `first-principles`。

## 原則

1. **單一論證。** 引言提出一個主問題與其子問題。每一節回應其中一個，並以它的答案作結。結論依相同的順序與用詞回答這些問題。這個結構稱為閉環（closed loop：引言提出的問題由各節逐一回答，結論再依同樣順序回答）。
2. **論點的順序：理由、描述、分析、結論。** 只有描述的段落尚未完成；每個實驗段落以「結果代表什麼」作結。
3. **數字放在表與圖。** 內文只引用承載論點的一兩個數字，且全文使用同一格式：絕對差值，括號內寫相對變化，例如 +0.030 (+6.0%)。不逐一列出數值範圍與表格儲存格。
4. **平實的語體。** 短句、少用括號、不用破折號連接句子、使用標準術語、不用比喻與自誇的形容詞。語氣肯定、陳述事實，讀起來像人寫的文字。
5. **主張在寫出的位置成立。** 量化主張（「至多」「從未」「在所有資料集」）在資料、模型或使用者群改變時，都要對照結果檔重新驗證。優先使用指名資料集的範圍，避免全稱的上界。
6. **關鍵但書留在正文。** 結果依賴協議時，正文用一句話加關鍵數字說明；完整表格放附錄。

## 正文與附錄

正文放：問題與研究問句、足以重現想法的方法描述、主要比較、回答每個核心問題的分析（各用一張表或一張圖）、每項穩健性檢查（robustness check：換一種設定重做，確認結論是否維持）的一句話加關鍵數字、指明主張及其適用範圍的限制，以及結論。

附錄放：設定、參數搜尋網格與 prompt、硬體與版本、各資料集細節、完整穩健性表格、其他基線（baseline：比較對象）、推導、更多案例。

判斷方式：拿掉某個段落或圖表後，若正文的每項主張仍有證據支持，就移到附錄。下表摘要自 `references/body-appendix.zh.md`。

| 內容 | 正文 | 附錄 |
|---|---|---|
| 問題、研究問句、貢獻 | 是 | 否 |
| 方法：公式與每個元件的設計理由 | 是 | 推導、實作細節 |
| 資料集：名稱、規模、以一段或一張小表說明協議 | 是 | 前處理、篩選條件、表中以外的統計 |
| 基線：清單，每項一行說明與來源 | 是 | 設定、搜尋空間、版本、硬體 |
| 主要比較表 | 是 | 各使用者群或次要指標的版本 |
| 主要主張的顯著性或區間 | 標記或差值欄 | 完整區間表 |
| 回答每個核心問題的分析 | 各一張表或一張圖 | 其他變體、敏感度掃描 |
| 穩健性與協議敏感度 | 每項檢查一句話加關鍵數字 | 完整表格 |
| 成本與延遲 | 一張圖或一張精簡表 | 含所有欄位的完整成本表 |
| 案例分析 | 支持核心主張時放一個精簡例子 | 其他案例 |
| 限制 | 指明主張及其適用範圍 | 無 |
| prompt、模板、網格、模型版本、倫理細節 | 否 | 是 |

四項檢驗：

1. **移除檢驗。** 拿掉後正文每項主張仍有證據支持，就移到附錄。
2. **自足檢驗。** 只讀正文時，每項主張都有證據、每個符號都有定義、每個關鍵但書都看得到。
3. **引用檢驗。** 每個附錄章節在正文中被引用一次，位置在讀者會想查閱之處。
4. **單一 PDF 檢驗。** 會議只收一份 PDF 時，不另附補充檔；併入附錄並維持在總頁數內，或刪除。

各會議的規定不同，投稿前要查目標會議最新的徵稿說明：內容頁數、是否接受獨立補充檔、附錄是否計入總頁數。

## 表格

- 一張表一個問題。讀者要做的比較放在相鄰的欄，或另設差值欄。
- 一個數字只出現在一張表。共用列或欄的表格要合併；獨立的區間表改為主表中的差值欄或顯著性標記。
- 主要指標放最前面；篇幅不足時，次要指標移到附錄。
- caption（圖表標題說明）的第一句寫這張表呈現什麼，之後最多兩個短句說明符號與縮寫。表格的 caption 放在表上方。
- 經典版面：用 booktabs（LaTeX 的表格套件）的上、中、下橫線，不用垂直線，不加底色；小數位數固定並對齊小數點；最佳值用粗體，次佳值只在比較需要時加底線；每張表的資料集與方法順序相同。
- 方法類別之間用橫線分隔並加簡短組名；每個標記符號在 caption 說明，標記種類愈少愈好；優先使用單欄表格，跨欄的寬表只用來呈現主要比較。
- 修改產生表格的程式，不直接修改產出的檔案。

常見的合併方式（摘要自 `references/tables-and-figures.zh.md`）：

| 情況 | 合併方式 |
|---|---|
| 主結果表之外，另有一張帶區間的成對差值表 | 合為一張：加上對最強基線的差值欄，或標記區間不含零的儲存格；完整區間表放附錄 |
| 每個穩健性變體各有一張表（不同負例、不同時間錨點） | 一張表，變體為欄組，只保留主張需要的方法列；或正文每個變體一句話，表放附錄 |
| 消融（ablation：拿掉某個元件，看效果掉多少）表與另一張「單獨使用某元件」表 | 合為兩個區塊的一張表，或正文只留移除區塊 |
| 成本表與成本圖呈現相同數字 | 圖放正文（品質對成本），表放附錄 |
| 設定、網格、prompt | 只放附錄 |
| 同一張表在不同使用者群重複（開發群與確認群） | 正文放確認群或全體；其他群放附錄 |
| 低於既定門檻的小幅變動 | 合成一行附註，不逐列呈現 |

## 圖

- 向量格式（PDF 或 PGF，後者是 LaTeX 的繪圖格式），縮放後的字體大小與正文一致。
- 全文使用同一組色盲友善的配色；每個序列另加第二種編碼（標記形狀或線型）。
- 座標軸簡潔：淺色格線、圖內不放標題（由 caption 負責）、圖例放在圖內或共用。
- caption 放在圖下方，第一句寫發現。
- 總覽圖的標籤與內文的章節、模組名稱一致。
- 一張圖一個訊息；多個子圖仍回答同一個問題，否則拆開或移到附錄。

## 寫作規則重點

摘要自 `references/writing-rules.zh.md`，其中每條規則都註明它防止的問題。作者給出新規則時，在同一次變更加進該檔。

**結構**

- 引言提出一個主問題與兩三個子問題；結論依相同順序與用詞回答。
- 每一節開頭寫它服務的問題，結尾寫答案（一句粗體小結，或段落的最後一句）。
- 摘要與引言最多列兩三個亮點；次要發現變成亮點底下的證據。
- 摘要明確列出貢獻，每項附一個數字；貢獻與章節一對一對應，並寫明對應關係。

**句子**

- 短句，一句一個主張；一句同時帶結果、條件與但書時，拆成兩三句。
- 括號內的細節移到表格、註腳或附錄。例如「前 1,000 位使用者、99 個抽樣負例、seed 0」寫在表格標題說明一次即可。
- 已有名稱的概念使用標準術語，例如 truncation（截斷）。
- 技術敘述不用比喻與擬人。例如將「誤差線仍蓋住基線」改為「信賴區間與基線重疊」。
- 不用「是 X，不是 Y」的對比句，直接陳述觀察，例如「三項檢查結果均落在雜訊範圍內」。
- 不用自誇的形容詞（例如 remarkable、superior、novel paradigm）。數字支持時可以明確主張，例如「超過每個訓練式基線至少 5%」。
- 原因未查明時寫「原因未查明」，後文不補推測性的原因。
- 學術與專業語體，既不寫成工程紀錄，也不生硬；正文移除執行編號、檔名與日期。

**數字**

- 全文一種格式：絕對差值，括號內寫相對變化，例如 +0.030 (+6.0%)；摘要可以只用相對變化。
- 內文只引用承載論點的一兩個數字，其餘留在表中。
- 每個指標的小數位數固定；多數推薦系統論文對 NDCG（排序指標）與 HR（命中率）用三位。百分比由未四捨五入的值計算。
- 區間包含零的比較，寫成「相當」或「在…範圍內」並附區間，不寫「優於」。
- 內文中的每個數字，都要存在於表、圖或附錄，也存在於結果檔。

**主張與證據**

- 資料集、模型或使用者群改變時，重新驗證每個量化主張（至多、從未、所有、每個、兩者皆）。
- 關鍵但書與其數字寫在正文，完整證據放附錄。
- 揭露重複執行之間的任何挑選；較好的做法是不依測試分數在多次執行中挑選。
- 看過結果之後才更換資料集時，寫出獨立於結果的理由（例如時間戳記記錄評分輸入的時間，無法代表消費發生的時間），或把該資料集的結果留在附錄。
- 沒有公開權重的託管模型要標明；主要主張盡量建立在可重現的模型上。

**內文中的圖表**

- 用小表或小圖取代列舉設定或數值的段落。
- 每個圖表在出現之前先在內文引用，並說明要看什麼。
- 草稿中尚在執行或待補的格子保持空白，不自行編造空白的原因。

## 步驟

1. **盤點。** 各節字數、各節圖表數、標題說明與附註的長度、跨表重複的數字、編譯後的頁數。
2. **對應。** 為每個段落與圖表標出它服務的問題，再標記保留、刪除、移動或合併。
3. **預算。** 依頁數上限設定各節字數。雙欄、八頁的論文通常容納約 5,000 到 5,500 字與六到八個圖表；這只是起始估計，要以編譯結果確認。
4. **改寫。** 依閉環順序逐節改寫；表格由各自的產生程式重新產生；重新編譯，逐頁檢查超出欄寬的行、分頁、圖表位置、表格寬度與圖的字體。
5. **重新驗證。** 每個數字與量化主張都對照結果檔。搜尋原始檔中每個量化用語與每個資料集名稱，逐一對照結果檔。
6. **語言檢查。** 先搜尋破折號、被禁用的形容詞、比喻與「不是 X，而是 Y」的句型；再由兩位獨立的檢查者（不同模型家族或不同的人）各做一次，最後由作者確認。
7. **記錄。** 每項修改記下它依據的規則。作者給出新的寫作規則時，在同一次變更把它加進 [references/writing-rules.zh.md](references/writing-rules.zh.md)。

## 輸出

一份計畫（盤點、對應、預算）、分支上修訂後的原始檔、把每項編輯對應到規則的變更紀錄，以及編譯後的 PDF。以對話使用的語言向作者回報。
