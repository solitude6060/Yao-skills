# 投稿套件與發布

英文版 [submission-and-release.md](submission-and-release.md) 為執行規範。

論文離開專案前最後一個階段的檢查：頁數關卡、會議規定、匿名程式碼發布、雙語版本與建置檔交付。每條規則都來自
一次投稿週期中差點出錯的情況；下面的會議細節只是例子，每次都要讀目標會議當期的徵稿說明（call for papers）。

## 頁數限制是建置關卡

- 超過內容頁數或總頁數限制的建置檔，不論文字多好，都不是投稿候選版本。每次增加文字或圖表後都重新編譯，並把
  頁數連同 commit 一起記錄。
- 照徵稿說明的算法計算：內容頁、參考文獻、附錄，以及單一 PDF 的總頁數。有些會議對超過總頁數的 PDF 直接
  desk-reject（不送審即拒稿）。
- 需要刪減時，先套用正文與附錄的判斷方式（[body-appendix.zh.md](body-appendix.zh.md)），再縮短句子。

## 依當期徵稿說明檢查會議規定

每次投稿都完整讀過徵稿說明與出版者的作者政策，記錄讀的版本或日期，並逐項檢查下表。回報某一項缺漏之前，先搜尋
論文全文；某個聲明可能放在預期之外的章節。

| 項目 | 檢查 |
|---|---|
| 格式 | 範本、document class 選項、字型、頁面大小、作者欄與 metadata（中繼資料）是否匿名 |
| 主題或 track 聲明 | 徵稿說明有要求時，第一頁說明論文與會議主題或所選 track（投稿類別）的關係，位置與措辭依徵稿說明允許的方式 |
| AI 使用聲明 | 簡短說明 AI 工具用在哪裡（例如程式實作與語言潤飾），並說明研究問題、協定與分析由作者決定、作者負責；放在徵稿說明或出版者政策允許的位置 |
| 參考文獻格式 | 書目樣式，以及任何規定的參考文獻格式區塊 |
| 補充材料 | 是否接受另外的檔案，或全部放進同一個 PDF |
| 預印本政策 | 是否可以張貼匿名預印本（preprint）或必須引用它，以及對標題或時間點的規定 |
| 同時投稿 | 一篇在某會議審查中的論文，不同時投到另一個會議；備案會議是之後的計畫，不是平行進行的計畫 |
| 程式碼可用性 | 審查期間能否附程式碼連結，以及連結要如何匿名化 |

## 雙盲審查下的程式碼發布

1. 在一個獨立、乾淨的 repository 建立發布版本；絕不發布工作用的 repository。
2. 只放論文重現結果所需的內容：不放私人路徑、使用者名稱、帳號名稱、內部文件或計畫、論文以外的資料集或實驗；
   README 裡的結果數字或調好的設定，不超出論文寫的內容。
3. 確認必要部分都在：資料準備、方法、評估、重現每張表的指令，以及作者署名為匿名的授權或使用條款檔。
4. 掃描發布 repository 的完整歷史（不只最後一個 commit），找名字、路徑、帳號、金鑰與會議名稱；以匿名作者身分
   commit。
5. 匿名鏡像（anonymous mirror）更新後，列出它的檔案，逐一比對每個檔案與發布 commit 的雜湊值。鏡像若仍提供
   較舊的 commit，就更新後再檢查一次。
6. 審查仍為匿名期間，不要在匿名鏡像會複製的 repository 加上真實姓名。
7. 程式碼連結放在目標會議優秀論文放的位置；查看該會議近期錄取論文的摘要與緒論。

## 預印本

審查期間張貼預印本之前：檢查徵稿說明與出版者的預印本政策；建置不含會議名稱、也沒有可辨識投稿的範本標記的
預印本；確認每位共同作者同意；並記住已張貼的預印本與其授權無法撤回。

## 雙語版本

- 每次修改都在同一個變更中同時改兩個版本；兩個版本共用數字、表格與術語。
- 圖中文字、圖例與圖說使用各版本的語言。
- 內文術語與主表的標籤一致。
- 每個版本都編譯並記錄頁數；任一版本超過限制，整個投稿套件就不能送出。

## 建置檔交付

- 每個建置檔都連同它所根據的 commit 一起交付，放在同一個固定位置，每個版本都要。
- 只交付最新的建置檔；比作者已看過的修改還舊的建置檔，絕不交付。
- 顯示相同數字的頁面、結果表與論文，從同一個 commit 一起發布。

## 一般化案例

- 一份超過總頁數限制的草稿，差點被當成投稿候選版本，而該會議會對超過總頁數的稿件直接拒稿。
- 一次規定檢查回報缺少 AI 使用聲明，但聲明其實在另一個章節；當時只搜尋了附錄。
- 匿名鏡像提供的 commit 比發布 repository 舊，直到更新並逐檔比對後才一致。
