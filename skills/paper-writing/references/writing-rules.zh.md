# 寫作規則與範例

英文版 [writing-rules.md](writing-rules.md) 為執行規範。

規則整理自作者對整篇論文草稿的修正、指導教授的意見，以及一次投稿前的審查。每條規則都註明它防止的問題。作者每提出一條新規則，就在同一次變更把它加到這裡。

## 結構

| 規則 | 防止的問題 |
|---|---|
| 引言提出一個主問題與兩三個子問題；結論依相同的順序與用詞回答。 | 論文只報告結果，卻沒說這些結果回答什麼。 |
| 每一節開頭寫它服務的目的或證據，不用自問自答的問句；結尾用平實的最後一句寫出答案，不用粗體（可對照目標會議強論文的結果段落：很少以問句開頭，也很少用粗體標出結論句）。 | 讀起來像數字清單的章節，或像作者在跟自己對話。 |
| 每個論點依序寫理由、描述、分析、結論。 | 只描述、不分析（「只描述，從不下結論」）。 |
| 摘要與引言最多列兩三個亮點；次要發現成為亮點底下的證據。 | 幾個分量相當的主張互相稀釋。 |
| 摘要明確列出貢獻，用文字說明主要結果；最多一到兩個數字，每個數字寫明它對應的比較或資料集（可對照目標會議強論文的摘要）。 | 摘要只敘述方法，讓讀者自己猜貢獻；或讀起來像一張結果表。 |
| 貢獻與章節一對一對應，並寫明對應關係。 | 沒有任何章節支持的貢獻。 |

## 句子

| 規則 | 修正範例 |
|---|---|
| 短句；一句一個主張。 | 一句同時帶結果、條件與但書時，拆成兩三句。 |
| 少用括號。括號內的細節移到表格、註腳或附錄。 | 「（前 1,000 位使用者、99 個抽樣負例、seed 0）」寫在表格標題說明一次即可，不必每句都寫。 |
| 不用破折號連接句子。數字範圍的破折號可以用。 | 把「X——而 Y——Z」改成兩句。 |
| 使用標準術語；已有名稱的概念不另造說法。 | 用「截斷」（truncation），不用「超長度」。 |
| 技術敘述不用比喻與擬人。 | 寫「信賴區間與基線重疊」，不寫「誤差線仍蓋住基線」。 |
| 不用「是 X，不是 Y」的對比句；直接陳述觀察。 | 「三項檢查結果均落在雜訊範圍內。」 |
| 不用自誇的形容詞（remarkable、superior、novel paradigm）。數字支持時，可以明確主張。 | 寫「超過每個訓練式基線至少 5%」，不寫「驚人地優於」。 |
| 論文中不出現尚未查明的原因：查明原因，或刪掉這句話、把觀察保留在附錄。內部紀錄（日誌、報告）寫「原因未查明」，後文不補推測性的原因。 | 從結果段落刪掉「原因未查明」；觀察移到附錄的表中，不附原因句。 |
| 學術與專業語體，不寫成工程紀錄，也不生硬。 | 正文移除執行編號、檔名與日期。 |

## 數字

| 規則 | 防止的問題 |
|---|---|
| 全文一種數字格式：絕對差值，括號內寫相對變化，例如 +0.030 (+6.0%)。摘要可以只用相對變化。 | 讀者要自己在不同格式之間換算。 |
| 內文只引用承載論點的一兩個數字，其餘留在表中。 | 機械式逐格複誦。 |
| 每個指標的小數位數固定（多數推薦系統論文對 NDCG 與 HR 用三位）。內文引用的差值等於表中兩格印出數字的差，或由一條寫明的四捨五入規則涵蓋所有引用的差值。 | 內文引用的差值與表中兩格印出數字的差相差一個單位。 |
| 區間包含零的差值，寫成「在此樣本數下沒有顯著差異」，不寫「相當」或「優於」。只有整個區間落在執行前宣告的容許範圍（margin）之內，才主張等價（見 `explain-the-number`）。區間數值放在表格或附錄，不寫進內文。 | 對不顯著的差值寫「優於」或「相當」；把缺乏證據寫成等價；內文塞滿區間上下界。 |
| 內文中的每個數字，都存在於表、圖或附錄，也存在於結果檔。 | 無法追溯來源的孤立數字。 |

## 主張與證據

| 規則 | 防止的問題 |
|---|---|
| 資料集、模型或使用者群改變時，重新驗證每個量化主張（至多、從未、所有、每個、兩者皆）。 | 在舊資料成立、在新資料失效的界限。 |
| 依賴協定的結果，正文用一句中性的話指出條件並指向附錄的表；數字、區間與完整比較放附錄。這句話可以寫出預設協定的理由，並引用它所依循做法的文獻。不用粗體，不寫負面的結論句。部署限制寫成條件：寫「要達到次秒級服務需要更快的硬體」，不寫「超出服務預算，且遠慢於訓練式模型」。 | 正文讀者看不到的但書，或正文自己反駁自己的主張。 |
| 維護一份流程揭露的必留清單（must-keep list）：開發用的使用者與用途、挑選規則與其讀取的資料、受評使用者的曝光情形。每次改寫後對照清單；這些句子可以縮短或移到附錄，不能刪除。 | 改寫時刪掉的揭露，之後被審稿人指為隱瞞的流程。 |
| 關於流程的敘述要字面上為真。寫流程實際做了什麼（「測試目標從未用於挑選」），不寫與紀錄矛盾的更廣保證（開發用使用者的測試目標曾被檢視過時，寫「從未看過測試集」）。 | 關於流程的錯誤陳述。 |
| 每個標題用詞都對照投稿會議所屬文獻採用的定義；指導教授會評審論文時，也對照指導教授的定義；兩者不同時，在論文中定義該詞（例如讀者預期「個人化」（personalized）需要使用者層級的參數時，相同歷史給出相同輸出的方法可以改稱「依使用者」（per-user）或「依歷史條件」（history-conditioned））。 | 針對主要主張的定義性質疑。 |
| 不寫未經檢驗、暗示本方法自身元件有問題的句子：不用把本方法加入的部分當成比較對象的句型，也不順帶暗示它的某個訊號帶有本文沒有檢驗的偏差。量測到的元件負面效果（例如消融實驗中加入它反而降低指標）仍要報告，並寫明條件與證據階段。 | 自己製造的反對意見，或論文漏掉負面證據。 |
| 揭露重複執行之間的任何挑選；較好的做法是不依測試分數在多次執行中挑選。 | 以測試集挑選的結果被當成成果。 |
| 看過結果之後才更換資料集時，寫出獨立於結果的理由（例如時間戳記記錄評分輸入的時間，無法代表消費發生的時間），或把該資料集的結果留在附錄。 | 「資料集是事後挑選」的質疑。 |
| 沒有公開權重的託管模型要標明；主要主張盡量建立在可重現的模型上。 | 針對主要結果的可重現性質疑。 |
| 正文不寫內部時間順序：哪個資料集或模型何時加入、開發順序、查詢日期、只在一個資料集多跑的 seed。論文描述最後的研究；流程細節放附錄。 | 讀者把開發歷程誤當成協定的選擇。 |
| 不寫推測性的疑慮：沒有機制或證據的可能差異，不寫成限制。主要主張所依賴、卻沒有執行的檢查，寫一次作為該主張的適用範圍，或去執行這個檢查。 | 沒有數字支持、自己製造的反對意見；對讀者隱藏的效度缺口。 |

## 文字的來源

| 規則 | 防止的問題 |
|---|---|
| 作者核定的文字（已送出的摘要、作者改寫過的貢獻列表）存成有版本的檔案。之後的修改由它開始，不得悄悄改回舊版。 | 核定過的措辭退回較舊的版本。 |
| 其他模型的改寫與審查只當作想法來源。採用其措辭前，先把每項事實對照結果檔；每個數字都由表格產生程式重新產生。結果檔不支持的空格理由或列的挑選，一律不採用。 | 編造的理由與選錯的列進入論文。 |
| 雙語論文的每項修改在同一次變更中同時改兩個版本；圖中文字與圖說使用各版本的語言；用詞與主表一致。 | 兩個版本內容不一致。 |

## 內文中的圖表

| 規則 | 防止的問題 |
|---|---|
| 用小表或小圖取代列舉設定或數值的段落。 | 密集的列舉式文字。 |
| 每個圖表在出現之前先在內文引用，並說明要看什麼。 | 讀者得自行解讀的圖表。 |
| 草稿中執行中或待補的格子保持空白，不加說明；不編造空白格的原因。 | 標題說明中未經查證的陳述。 |

## 最後檢查

1. 搜尋原始檔中每個量化用語與每個資料集名稱，逐一對照結果檔重新驗證。
2. 搜尋破折號、被禁用的形容詞、比喻、「不是 X，而是 Y」的句型、句首的問句，以及結果段落中的粗體片段。
3. 編譯後逐頁檢查：超出欄寬的行、圖表位置、表格寬度、圖的字體。
4. 兩次獨立的語言檢查（不同模型家族或不同的人），最後由作者確認。
5. 查核每筆參考文獻：它存在、書目資料正確、引用的主張確實出現在原文中。參考文獻通過第三步之後才保留（`research-survey` 的引用查核階梯，citation ladder）。
6. 對照目前的文字檢查必留揭露清單，並把每個引用的差值與表中印出的數字對照。
7. 雙語論文要比對兩個版本的修改、數字與用詞是否一致。
