# 矯正重複錯誤

英文 [SKILL.md](SKILL.md) 是執行規範。改編自 Lauren Tan 的 pstack `correct`
（MIT，`cursor/plugins` 的 `1ba91fc`，見 `LICENSE`）。只在使用者明確呼叫時使用。

使用者一直在這個 repo 裡糾正 agent 犯同樣的錯。目標是改 repo，讓下一個 agent 犯不了。
假設每個貢獻者都只看它打開的檔案、複製最近的範例、走最短能通過的路。

## 找出錯誤類別

只看這個 repo：近期 commit、revert 與修正 commit；review 文件、fix log 與分流表；
`AGENTS.md`、`CLAUDE.md` 與專案記憶；本 workspace 的 agent 對話紀錄（Claude Code 在
`~/.claude/projects/<workspace-slug>/*.jsonl`）中使用者的糾正；解釋 workaround 的註解。
分組成類別，發生兩次以上才算一類，每次發生都記下 commit、檔案或對話行號。

## 在最高可行層級修掉

1. **架構**：每份狀態只有一個擁有者、每件事只有一種支援做法；隱藏內部讓錯誤 import
   失敗；手動同步的清單改成單一來源；刪掉會被複製的舊做法和死碼。
2. **型別與檢查**：讓錯誤狀態寫不出來；做不到就加 lint、validator 或 CI 檢查，
   錯誤訊息直接指出該用哪個檔案、型別或函式。既有模式很多時，只擋新增的。
3. **行為測試**：修掉或刪掉「行為壞了還會過」或「只改內部就會壞」的測試。
4. **文件或 agent 規則最後才用**，只留給需要判斷的情況，因為 agent 跳過時不會有任何東西失敗。

研究 repo 常見類別：split 之間的資料洩漏、各腳本的指標或候選集定義不一致、結果寫到暫存區、
回報數字沒有出處。優先寫一個在真實過去案例上會失敗的 validator 或測試。

## 修正與證明

照專案的分支、測試先行與 PR 規則；最常見的類別先修，一類一個 commit；每個新檢查都要
證明在真實過去錯誤上會失敗並保留失敗輸出；本機與 CI 跑同一個指令；例外寫在該行，
附理由、到期日與使用者同意。

## 規則表

在 agent 指示檔維護「規則／由什麼強制／過去錯誤」表。再次被糾正時修掉錯誤並加規則；
規則已存在卻沒有東西強制，就視為重犯，在同一個改動裡往更高層級移。錯誤不可能再發生時
刪掉該規則。

## 回覆

每個類別附證據、選擇的層級與為何更高層級做不到、先失敗後通過的輸出，以及留給使用者
決定的類別。
