# 論文論證：動機、亮點、方法、證明

英文 [SKILL.md](SKILL.md) 是執行規範。分析方法的文獻來源在 [references/analysis-catalog.zh.md](references/analysis-catalog.zh.md)。證據階梯、審稿人質疑與常見陷阱在 [references/evidence-ladder.zh.md](references/evidence-ladder.zh.md)。顧問的問題與作者的調整在 [references/advisor-questions.zh.md](references/advisor-questions.zh.md)。

結果只能說明方法有效。論文還要說明三件事：為什麼有效、每個部分貢獻了什麼、這樣設計為什麼合理。
這個 skill 依照指導教授拆解論文的四個部分來整理論證，並規劃第四部分「證明」需要的證據。這一部分最常缺。

## 何時使用

- 已經有結果，方法很簡單（加權和、凍結模型加統計量、檢索混合），但內文只寫了做法，沒寫為什麼有效。
- 和指導教授開會前、投稿前，或被問到下面這類問題之後：「這樣調合理嗎？」「個人化在哪裡？」「這個元件補了什麼？」
- 規劃分析時，用來決定哪個分析支持哪個主張，以及哪些放正文。

不適用：實驗協議本身是否有效，請先用 `recsys-evaluation`；檢查沿用下來的假設，請用 `first-principles`。

## 四個部分

每部分寫一段，最後整理成論證對照表。每一段都要指出支持它的證據。

1. **動機。** 成本與應用環境引出痛點，痛點引出研究問題。關鍵詞要精確定義。
   - 例如 training-free（不訓練）要寫清楚：什麼從不更新、什麼仍在驗證資料上挑選、挑選要花多久。
   - 「泛化」需要凍結設定、直接搬到新領域的測試。各領域各自挑設定，只能證明可調整性。
2. **亮點。** 最多兩到三件讀者應該記住的事；摘要把它們列為貢獻，每項附一個數字。每個亮點對應一個結果或一個分析；沒有證據的亮點刪掉，或改列未來工作。
3. **方法。** 每個元件寫清楚：
   - 帶什麼資訊、資料來源與時間尺度、補了其他元件沒有的什麼（「我補了什麼」）。
   - 用兩個軸分類：
     - 全域（全體統計）對局部（以使用者或查詢為起點）。
     - 靜態對動態（時間衰減、與順序有關）。
   - 寫明哪些量因人而異（各項貢獻、閘門），哪些是全域共用（權重）。
4. **證明。** 說明為什麼有效與其機制（mechanism：分數變好的原因），不只是指標上升。用下面的證據階梯規劃，再站在審稿人角度檢查一次。每個元件回答三個問題：它代表什麼、為什麼選它、為什麼有效；每個答案都有三層：原理、使用同一原理的文獻、本文自己的證據（見 [references/advisor-questions.zh.md](references/advisor-questions.zh.md)）。

## 證明的證據階梯

主張需要到哪一階，就做到哪一階。介入式分析（intervention：直接改變輸入或元件，看結果怎麼變）比相關性分析強；每個分析都要標明屬於哪一種。

| 階 | 問題 | 常用分析 |
|---|---|---|
| 1 效用 | 有沒有用？ | 主表、逐人配對差、使用者層級的 bootstrap 區間 |
| 2 必要性 | 每個元件都需要嗎？ | 固定權重，逐項移除；並列重新選參後的移除；逐人列出變好、變差、不變的人數 |
| 3 資訊 | 元件用了什麼資訊？ | 輸入介入：拿掉輸入、換成條件相近的另一位使用者、只留最近 k 筆或最早 k 筆、反轉順序；把元件換成只帶單一因素的簡單版本（Xu et al. 2023） |
| 4 拆解 | 每個決定有多少來自各部分？ | 加法分數下，目標對負例的分差恰好等於各項差的總和；報告不受尺度影響的占比（主要用成對差，標準差占比作為穩健性檢查），再依資訊來源分組 |
| 5 權衡 | 為什麼這樣配權重？ | 兩部分之間的內插曲線，標出實際使用的點，驗證與測試各一條（kNN-LM 圖 5）；逐一放大縮小各權重；最佳區域的寬度 |
| 6 互補 | 為什麼要相加，不只用一個？ | 命中列聯表（都中、只有甲中、只有乙中、都沒中）、救回與失去的數量、取兩者較好時的上限；相關與不相關項目的重疊（Lee 1997）；各項的區分度 d（Vogt and Cottrell 1999） |
| 7 條件 | 在哪些情況有幫助？ | 依事先宣告的屬性分層（商品熱門度、歷史長度、證據是否存在）；事後分組只做描述（kNN-LM 的罕見樣式、Drozdov et al. 2022 的相似度分組） |
| 8 穩定性 | 選出的設定有意義嗎？ | 選參分組、從未參與選參的使用者、其他候選抽樣方式；主張「效果」穩定，不主張原始權重穩定 |
| 9 案例 | 讀者能看懂一個決定嗎？ | 依事先寫定的規則挑案例（例如分數變好、不變、變差三組中，各取最接近中位數者），包含失敗例，列出每一項的貢獻 |

## 步驟

1. **讀論文與指導教授的筆記。** 手寫筆記逐行寫出解讀，不確定的字標出來。只有兩種解讀會導致不同工作時才發問。
2. **寫出四個部分，並整理論證對照表。** 每段一段文字；對照表的欄位依序是：主張 → 證據 → 類型（介入、相關、描述）→ 狀態（已有、規劃中、缺）→ 位置（正文、附錄）。
3. **寫共同背景說明，請顧問各自規劃。**
   - 背景說明包含：方法公式、元件表（來源與時間尺度）、目前結果、可用資料與算力、專案規則。
   - 請兩到三位互相獨立的顧問，來自不同模型家族或不同的人，提出分析計畫和審稿人最強的五個質疑。
   - 顧問一律唯讀，事後要檢查有沒有改動檔案。顧問給的預期數字只當猜測，不能當事先宣告的判讀。
4. **先建所有分析共用的資料。** 加法分數的情況是：每個查詢、每個候選一列，含各原始項、閘門、權重、貢獻、總分與排名。必須能逐筆重現正式結果，重現不了就停下來。
5. **先宣告判讀，再計算。** 每個分析先寫下預期結果，以及哪種結果會推翻主張。先跑便宜的 CPU 分析，小規模 GPU 介入同時進行。
6. **照實回報。** 每項判讀標為成立、部分成立或不成立，附數字與來源。不成立的判讀不得升格為主張。
7. **分配論文篇幅。** 正文最多一張圖（通常是內插曲線加一個介入結果）和一張小表（拆解占比、救回與失去），其餘放附錄。文字用 `paper-writing` 撰寫：閉環結構（引言提出的問題由各節回答，結論依同樣順序回答）、正文與附錄的分工、表格。

## 審稿人角度（投稿前檢查）

| 質疑 | 回應方式 |
|---|---|
| 「大網格配少量使用者，會過度擬合。」 | 選參分組、未參與選參的使用者、最佳區域寬度；主張效果穩定，不主張權重穩定 |
| 「權重只是在補尺度差異。」 | 不受尺度影響的貢獻與精確分差；不同項之間不比原始權重 |
| 「沒有個人化，只是熱門度。」 | 在以使用者為起點的各項與模型輸入中，換成他人的歷史；依資訊來源分組的占比 |
| 「模型只是加了商品先驗，或讀到輸入裡附帶的證據，沒有使用者資訊。」 | 無歷史與相近他人歷史兩種介入；把輸入裡附帶的證據拿掉，當作另一個條件 |
| 「增益來自候選抽樣方式或位置。」 | 換一種抽樣方式重做拆解；檢查位置或順序，否則在限制中寫明 |

## 常見陷阱

- 原始權重不等於重要性：各項尺度不同，還有逐查詢標準化。
- 在同一批使用者上選參又測試，結果偏樂觀；要引用未參與選參的使用者和選參分組。
- 同分排序規則可能藏著被移除的元件（例如模型信心），移除時要一起拿掉。
- 日期還看得到時，反轉清單只測到「清單位置」，測不到時間順序。
- 輸入已含協同證據時，資訊來源是混合的，先分離再歸因。
- 依答案事後分組只做描述，任何方法都不能看到分組。
- 某元件在某資料集沒有貢獻，就照實寫；要用資料集特性解釋，必須是量過的特性。
- 相關性分析不寫因果語句；已有標準術語的概念不另造新詞。

## 輸出

寫到專案的規劃資料夾：四個部分的摘要、論證對照表、附事先宣告判讀的分析卡，執行後再補上每項判讀結果的紀錄。以對話使用的語言向作者回報。
