# 基線與公平比較

英文版 [baselines-and-fairness.md](baselines-and-fairness.md) 為執行規範。

選擇比較方法、執行它們、或撰寫比較主張時閱讀。

## 依資訊取用範圍為基線分層

每個方法的資訊取用範圍都寫明後，比較才有可解讀的意義。依方法可以讀取的內容分組：

| 層級 | 方法可以使用的資訊 | 例子 |
|---|---|---|
| A. 自己的歷史加商品文字 | 目標使用者嚴格較早的事件、商品標題或描述、候選清單 | 凍結的 LLM 排序、字詞比對（BM25）、類別比對、近期性規則 |
| B. 再加跨使用者統計 | 對其他使用者訓練事件的計數或共現，沒有學習參數 | Popularity、item-kNN、共現規則、EASE（閉式解） |
| C. 再加目標領域的訓練 | 以目標領域訓練資料擬合的參數 | BPR-MF、NCF、SASRec、BERT4Rec、LightGCN、經微調的 UniSRec、經微調的 LLM 推薦器 |
| D. 零樣本遷移 | 只以其他領域擬合參數，不經目標領域更新就套用 | 未微調的預訓練文字式序列模型 |

主張按層級撰寫（「在只使用使用者自己歷史與商品文字的方法中……」），並說明方法勝過或接近哪些層級。把不同層級混在同一個排名中、又沒有標示，會掩蓋方法勝出的原因。

## 每個方法使用相同的輸入

對每個查詢，每個方法都必須使用相同的：使用者集合、目標事件、候選集合（候選清單的雜湊值）、可見歷史的切點（嚴格早於目標）、商品目錄，以及商品文字欄位（或說明差異）。記錄每個查詢的雜湊值，並在計算指標之前檢查。

## 來源忠實度

- 優先順序：作者官方程式碼 > 作者、版本與授權可追溯的可信公開實作 > 自行實作；每降一級都記錄理由。
- 固定儲存庫網址、commit 與匯入的檔案。模型結構、損失函數、抽樣、初始化與最佳化器依來源定義；只調整資料讀入與評估。
- 訓練式基線用相同的預算，並在驗證目標上調參。
- 背景：[Dacrema et al., RecSys 2019](https://arxiv.org/pdf/1907.06902) 檢視了頂級會議的
  18 個 top-n 演算法；只有 7 個能以合理的努力重現，其中 6 個常被簡單的啟發式方法超越（摘要）。
  [Rendle et al., 2020](https://arxiv.org/pdf/2005.09683) 報告，
  調得好的內積，顯著優於 NCF 所提出、由 MLP 學得的相似度（摘要）。
  宣稱進展之前，先納入調得好的簡單基線（popularity、item-kNN、EASE、BPR-MF）。

## Seed 與重複次數

| 方法類型 | 隨機性 | 執行次數 |
|---|---|---|
| 凍結的本地模型，確定性的 logit／似然讀取，固定的候選與順序 | 無 | 1 次；第二次執行作為確定性檢查 |
| 閉式解模型（EASE、popularity） | 無 | 1 次 |
| 訓練式模型（MF、SASRec 等） | 初始化、抽樣、資料順序 | 多個 seed；報告平均與離散程度 |
| 取樣解碼的 LLM 排序 | 解碼 | 多個 seed 或重複 |
| 託管的 API 模型 | 即使 temperature 為 0，伺服器端仍有非確定性 | 重複一個子集，並報告離散程度 |
| 候選順序置換 | 順序 | 固定順序 seed，或對多種置換取平均 |

跨 seed 時固定測試集（使用者、目標、候選）；只改變方法的 seed。
LLMRank 對至少三次重複執行取平均（[Hou et al., §3](https://arxiv.org/pdf/2305.08845)）。

## 執行失敗與方法失敗

- 執行失敗：記憶體不足、HTTP 5xx、當機、逾時、檔案遺失、連接埠衝突。它不是結果。重跑受影響的查詢直到成功；仍有未解決執行失敗的執行不納入報告。記錄嘗試次數與原因。
- 方法失敗：方法回傳無法解析或無效的輸出，或依設計無法為這個輸入排序（例如訓練式模型對這位使用者沒有目錄內的歷史）。保留在分母，效用為 0，並另列為獨立的計數。
- 每張結果表都在分數旁顯示失敗筆數。

## 在報告用的使用者上調參造成的選擇偏差

嘗試許多 prompt、讀取方式或方法變體，並在同一批使用者上報告最佳者，會高估分數（winner's curse，贏家詛咒）。規則：

1. 在開發用的使用者集合上調參；固定設定；在新的使用者上報告。
2. 最終執行擴大使用者樣本時，新增的使用者才是新的；在它們上面報告，或報告完整集合並另列開發子集。
3. 報告嘗試過多少個變體。

## 比較主張

- 優先在相同查詢上做成對比較（以使用者為單位的成對 bootstrap 區間），不只列各方法的分數。
- 相對主張（「在 X 之內」「勝過」）要註明層級、資料集、切分、候選協議與失敗筆數。
- 有效的負面結果與消融結果留在表中。
