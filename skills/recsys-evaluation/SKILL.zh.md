# 推薦系統評估方法

英文 [SKILL.md](SKILL.md) 是執行規範。細節與文獻來源在 `references/`。

切分方式、候選集合與前處理決定了分數代表什麼。多數無效比較的協議是沿用而來，
沒有從研究問題推導。設計實驗前跑一次檢查清單，結果寫進報告前再跑一次。

## 何時使用

- 設計或修改離線評估協議
- 從規格、論文或 repository 沿用切分、時間截止點、候選規則或資料集
- 比較資訊取用範圍不同的方法（凍結的 LLM 與訓練式模型）
- 結果出乎預期，或換協議後方向相反
- 撰寫協議章節、限制說明或審稿回覆

## 決策檢查清單（依序回答，寫進計畫檔）

1. **研究問題一句話**，寫明使用者是已有歷史的使用者，還是未見過的使用者。
2. **各方法的資訊取用**：推論時讀什麼（自己的歷史、商品文字、跨使用者統計），訓練時用了什麼。
3. **切分**：逐人 leave-one-out（LOO，留一法：每人最後一筆測試、倒數第二筆驗證）、
   global temporal split（GTS，全域時間切分）、user-disjoint（使用者隔離）或隨機切分；
   各自允許哪種洩漏、影響哪些方法。
4. **是否有方法跨使用者擬合**：沒有的話，全域截止點不保護任何東西，只會刪掉有效歷史；
   有的話，揭露跨使用者的未來資料，並規劃 GTS 敏感度檢查。未經量測不寫洩漏的影響方向。
5. **只有研究問題是未見過的使用者時才用使用者隔離**，並說明 ID embedding 模型如何 fold-in
   （以部分歷史推得新使用者表示）。避免意外變成冷啟動評估。
6. **目標取最後一筆**，不取「截止點後第一筆」（偏向較長的事件間隔）。
7. **官方切分檔**：該資料集版本有就直接用，記錄雜湊值。
8. **前處理寫清楚**：重複的（使用者，商品）怎麼處理、同時間事件依原始列順序（不用商品 ID）、
   k-core 與去重的先後。
9. **候選**：全排序、抽樣 1+n（均勻或依熱門度），或檢索後重排。抽樣結果只代表該候選分布。
10. **兩階段評估**：檢索器固定、報告端到端指標、計入檢索失誤、絕不把目標補進候選。
11. **輸入一致**：所有方法的使用者、目標、候選、可見歷史與商品文字相同，以逐題雜湊值證明；
    各方法看得到的歷史筆數相同。
12. **執行次數**：訓練式或取樣解碼的方法用多個 seed，雲端 API 重複查詢；宣稱只需一次前先做確定性檢查；不依測試分數在多次執行中挑選。
13. **調整用與報告用的使用者分開**，避免選擇偏差。
14. **失敗處理**：執行失敗（記憶體不足、HTTP 5xx、當機）重跑，不當作結果；方法失敗
    （輸出無效、設計上無法排序）留在分母、效用記 0，並另列筆數。
15. **LLM 方法**：候選順序、解析失敗、文字欄位、字詞與類別對照、歷史對調對照、
    相同快取條件下的成本、預訓練曝露。
16. **抽樣結果旁列出隨機期望值。**

第 1–6 題的答案若是「沿用規格」，協議就還沒準備好：重新推導，或寫 ADR（architecture decision record，架構決策紀錄）。

## 核心事實

- LOO 允許跨使用者的未來資料進入訓練；影響可正可負，也會改變模型名次（Ji et al., TOIS 2023，表 5–6）。
- GTS 的目標選 Last、Random 或 Successive，不選 First（Gusak et al., RecSys 2025，§4.2、§5）。
- 抽樣指標連期望值都不保證維持模型次序（Krichene & Rendle, KDD 2020）。
- n 個候選中目標名次為 r：HR@K = 1[r ≤ K]；NDCG@K = 1/log2(r+1)（r ≤ K）；MRR = 1/r。
  隨機排序：E[HR@K] = K/n；E[NDCG@K] = (1/n)·Σ_{r=1..K} 1/log2(r+1)；
  n = 20、50、100 時 NDCG@10 為 0.227、0.091、0.045。

## 警訊

| 觀察 | 可能原因 |
|---|---|
| 訓練式基線遠低於簡單規則 | 測試使用者未進訓練，或基線未調參 |
| 寫出「洩漏只對基線有利」 | 未經量測就斷言方向 |
| Popularity 低於隨機 | 依熱門度抽樣的負例 |
| 1+99 與全排序的方法次序相反 | 抽樣指標不一致 |
| 筆數與官方 benchmark 不同 | 去重與 k-core 順序或資料版本 |
| 目標出現在可見歷史；不同使用者歷史相同 | 重複規則；同時間事件依商品 ID 排序 |
| 重排分數高於檢索器召回率上限 | 目標被補進檢索清單 |
| 逐人挑最佳變體帶來大幅增益 | 用目標挑選的上限值 |
| 記憶體不足或 HTTP 500 的查詢被記為 0 | 執行失敗被當成方法失敗 |

## 報告

每張結果表寫明資料集與版本、切分與目標規則、候選協議、使用者人數、隨機期望值、
失敗筆數、seed 或重複次數，以及各方法的資訊取用層級。LLM 方法另列 token、延遲與成本。
揭露 LOO 的跨使用者未來資料，以及凍結模型的預訓練曝露。
