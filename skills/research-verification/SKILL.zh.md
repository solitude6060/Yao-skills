# 研究驗證

英文 [SKILL.md](SKILL.md) 是執行規範。範本：[verifier-brief](references/verifier-brief.zh.md)（驗證者任務說明）、
[answer-path-audit](references/answer-path-audit.zh.md)（答案路徑稽核）、[finding-triage](references/finding-triage.zh.md)（意見分流）。

產出結果的人最不適合檢查這個結果：他照自己的本意讀自己的程式，也預期會得到手上的數字。
驗證要在全新的唯讀上下文（fresh read-only context）中執行，把數值一致、契約符合與主張支撐分開判定，
並記錄哪些項目沒有檢查。

## 何時執行

| 觸發條件 | 範圍 |
|---|---|
| 每完成一到兩件重大工作（結果表、整合、論文修訂、已發布頁面）之後 | 上次驗證之後的項目 |
| 階段性合併（milestone merge）之前 | 該階段收錄的全部內容 |
| 投稿之前 | 每個數字、句子與表格及章節之間的一致性、每一筆參考文獻 |
| 增益看起來很大或過於整齊 | 答案路徑稽核 |
| 審查者、審查報告或代理（agent）回報問題，或回報某個來源的事實 | 意見分流 |

不適用：單一量測的上限與雜訊（[explain-the-number](../explain-the-number/SKILL.zh.md)）；沿用而未驗證的假設
（[first-principles](../first-principles/SKILL.zh.md)）；合併審查門檻（[triple-review](../triple-review/SKILL.zh.md)）；
diff（程式差異）以外的連帶損壞（[blast-radius](../blast-radius/SKILL.zh.md)）；產出者自己在收錄前做的計畫與實際比對
（[experiment-contract](../experiment-contract/SKILL.zh.md)）；本 skill 會獨立重做這項比對。

## 1. 驗證者任務說明（verifier brief）

開一個全新的唯讀上下文。會決定主張的結論（load-bearing claim），要用與產出者不同模型家族的模型驗證。
任務說明附上任務卡、擁有者要求的原文引述、原始檔路徑、要檢查的確切主張，以及三個問題：

1. 完整性：任務卡與擁有者要求的每一項是否都完成？
2. 正確性：依精確的列篩選條件，從原始檔重算一部分數字；並閱讀引用的程式或 diff。
3. 方向：這項工作是否服務研究問題與目前的優先順序？

驗證者要寫下它無法存取或執行的項目（某個裝置、某個服務、沙箱外的檔案）；不是它自己觀察到的內容，
要標明出處。結束後檢查它沒有修改任何檔案。

## 2. 判定欄位

分開回報三個欄位；任一欄位都不代表其他欄位成立。

| 欄位 | 問題 | 值 |
|---|---|---|
| 數值一致 | 重算的數字與回報的數字是否相符？ | 相符；不符（列出儲存格）；未檢查 |
| 契約符合 | 執行是否遵守約定的選擇目標、使用者群組、輸入與身分？ | 符合；不符（列出項目）；未檢查 |
| 主張支撐 | 證據是否支撐這句話的現有寫法？ | 支撐；縮小寫法後支撐；不支撐 |

通用案例：一項重新選參的分析重算結果完全一致，但它用的選擇目標與主研究不同，「等價」的寫法也沒有證據支撐。

## 3. 答案路徑稽核（answer-path audit）

增益看起來很大時，寫成文字之前先稽核：

- 逐元件的資料路徑證明：哪些欄位進入分數，用的是哪一個時間邊界。
- 被評估的目標，與每個元件讀取的所有資料（訓練資料、記憶、選參用的目標、快取）之間的集合交集；使用者互斥協定下，另外計算報告群的使用者身分，與任何目標（含驗證目標）曾用於開發或選參的使用者之間的交集，範圍包含本專案與共用資料的姊妹專案；預期為零。
- 由原始輸出獨立重算主要數字。
- 至少一位來自其他模型家族的審查者。
- 抽樣負例（sampled negatives）：只套用在負例、沒有套用在目標上的篩選規則，可以辨認出目標。
  只用該規則排序候選、不讀任何歷史；命中率遠高於隨機即是洩漏（leakage）。
- 模型輸入中的識別碼（identifier）：同一批候選只用識別碼規則排序，分數必須接近隨機。

## 4. 意見、來源與論文數字

- 每一則審查或代理回報的問題，動手前先對照來源查證：存在、部分存在、不存在，附 `file:line`。
- 「某項內容不存在」的主張，必須對整份文件或整個 repository（程式碼庫）做全文搜尋。
- 代理回報的來源事實（例如原作者用的設定），要回到該來源重新確認。
- 文字與表格測試必須在被刻意改錯的副本上失敗；拿數值和自己比較的斷言什麼都沒有驗證。
- 論文數字一律由產表程式重新產生，讀取已收錄的列；絕不從改寫建議中複製數字。
- 區間包含 0 代表「在此樣本數下差異不顯著」；只有整個區間落在執行前宣告的容許差距（margin）之內，才代表等價（見 [explain-the-number](../explain-the-number/SKILL.zh.md)）。
- 延遲只在同一裝置上比較；裝置不同時，在同一裝置上補量雙方的小樣本。
- 中斷、空白或只有結束碼的審查，不算核准。

## 輸出

在任務卡旁寫下：驗證紀錄（任務說明、驗證者身分、存取限制、三個判定欄位）、分流表（問題、來源、
證據、存在／部分存在／不存在、處置、理由）與修正紀錄（fix log）。用專案的對話語言，以一到兩行向擁有者
回報判定。檢查未通過時，只把受影響的工作退回前一個階段。
