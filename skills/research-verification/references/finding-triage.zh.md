# 意見分流

英文版 [finding-triage.md](finding-triage.md) 為執行規範。

來自審查者、外部審查、驗證者或 agent（代理程式）的一則意見（finding），是關於來源的一項主張。它的嚴重度標籤不是證據。採取行動之前，對照確切的 checkout（簽出的程式版本）、資料或文件查證。

## 分流表

| Id | 意見（簡述） | 回報者 | 宣稱的位置 | 查證的證據（`file:line`、指令與輸出） | 狀態 | 處置 | 理由 |
|---|---|---|---|---|---|---|---|

狀態值：

| 狀態 | 意義 |
|---|---|
| 存在 | 缺陷如描述般存在 |
| 部分存在 | 存在，但範圍較窄、原因不同，或影響不同 |
| 不存在 | 不存在；證據顯示原因 |

處置值：立即修正、修正並縮小主張、指定負責人並記錄後續項目後延後處理、附證據否決。HIGH（高嚴重度）的協定問題不能靠搬動文字延後；要用實驗回答（資訊對等對照）。縮小主張只能作為該實驗之外的補充，並需擁有者核准。

## 查證規則

- 在受審的確切版本中讀所引用的 `file:line`，不讀之後的 checkout。
- 「某項內容缺少」的主張（「沒有關於 X 的陳述」「沒有 Y 的測試」）需要對整份文件或整個 repository 做全文搜尋。通用案例：一次合規檢查只搜尋了附錄，回報缺少一項其實在正文中的陳述。
- 依據來源預設設定的意見，需要該次執行的實際設定。通用案例：一份審查從來源的預設值推論訓練長度；checkpoint（模型檢查點）紀錄顯示的是另一個值，該意見因此撤回。
- 改變整個系統的比較，無法分離單一元件；把效果歸因於單一元件的意見，需要一個只改變該元件的對照。
- Agent 回報的來源事實（原作者用了什麼、另一篇論文回報了什麼），在進入計畫或論文之前，回到來源重新確認。
- 文字與表格測試：在文件的副本中刻意加入一個錯誤（改一個數字、刪一句話），確認測試會失敗。通用案例：三個斷言拿數值和自己比較，任何輸入都會通過；一次突變測試（mutation run）揭露了它們。

## 中斷與空白的審查

中斷的審查（使用額度用完、逾時、當機）、空白輸出，或只有結束碼、沒有實質內容的審查，都不算核准，即使它產生了一些有用的意見。記錄下來，分流其中的部分意見，並在確切的版本上完成審查。核准只綁定它審查過的內容。

## 修正紀錄

```markdown
# 修正紀錄：<工作項目或審查>

| 意見 id | 狀態 | 重現方式 | 修正 | 新增的測試或檢查 | 動到的檔案 | 重新驗證者 |
|---|---|---|---|---|---|---|
```

在專案的 status 紀錄中交互連結分流表、修正紀錄與任何後續項目。
