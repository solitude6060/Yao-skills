# 影響範圍

英文 [SKILL.md](SKILL.md) 是執行規範。改編自 Lauren Tan 的 pstack `blast-radius`
（MIT，`cursor/plugins` 的 `1ba91fc`，見 `LICENSE`）。

用在一個看起來很小、但還不能信任的改動要上線或核准之前，或被問到「這會弄壞什麼」時。
列出呼叫端不是重點，grep 一秒就有；重點是 grep 看不到的破壞。

## 不要相信自己寫的分析

聽起來合理的分析不管對不對都很有說服力。找出這個改動「之所以安全」所依賴的一兩個事實，
用實際執行程式來證明。

證據等級（每個事實盡量往下推，並說明停在哪一級）：

1. 只是宣稱。
2. 指出 `file:line`，或依賴套件在鎖定版本的原始碼。
3. 一步步推演失敗情境，證明到不了。
4. 寫腳本或測試呼叫真正的程式，錯了會大聲失敗。
5. 在實際系統（app、pipeline、實驗）重現。

## 步驟

1. 讀改動：diff、增改刪的符號、行為差異（含 diff 沒寫明的部分）、commit 訊息和相關計畫。
2. 找出它安全所依賴的那一個事實，時間花在這裡。
3. 看 grep 看不到的地方：鎖定版本的套件原始碼、執行時機（import、非同步回呼、teardown、
   worker process、GPU stream）、序列化格式、檔名與欄位名、checkpoint 或快取、設定鍵、
   環境變數、feature flag、跨語言讀同一份資料、好幾層之後的下游。研究程式另查 seed、
   資料切分、指標程式與下游表格讀的結果檔。
4. 誠實評估每個風險的可能性與代價。已確認和已排除分開列。引用真實 `file:line`，
   不捏造呼叫端或 API。
5. 寫腳本或測試證明那個事實，執行並貼上輸出。
6. 範圍大或風險高的改動，依專案的模型分派規則請另一個模型家族獨立回答同一問題，
   只合併能驗證的發現。

## 交回內容

改動做了什麼（含不明顯的部分）；安全所依賴的事實、達到的證據等級與證明（證明不了就寫
「未證明」）；風險（怎麼壞、`file:line`、可能性與代價、怎麼查）；已排除項目；
merge 前最便宜的測試或重現腳本，專案規則要求時提交成回歸測試。公開前移除私人路徑、
憑證與未公開資料。
