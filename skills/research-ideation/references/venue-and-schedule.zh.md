# 投稿會議與時程

英文版 [venue-and-schedule.md](venue-and-schedule.md) 為執行規範。

依題目、貢獻與證據選擇投稿會議（venue），再對照該會議目前的徵稿說明檢查日期與規則。只看名氣或最近截止日選出的會議，常在主題契合度上出問題，或是太晚才發現規則限制。

## 從目前徵稿說明取得的資訊

讀官方的 call for papers（徵稿說明）與作者須知，不讀摘要整理或搜尋片段：

- 主題與 track（投稿類別），以及題目是否符合其中之一；
- 接受的貢獻類型（技術、資源、benchmark（基準測試）、分析）；
- 頁數上限，以及參考文獻與附錄是否計入；
- 摘要與全文截止日、rebuttal（作者回覆）期間、結果通知日；
- 匿名規則、preprint（預印本）政策、AI 使用聲明、參考文獻格式；
- 同時投稿與雙軌投稿規則，包括同一會議的其他 track。

每個日期都記下來源與讀取日期。通用案例：一個搜尋片段給的 rebuttal 期間與官方網頁不一致；官方網頁才是正確的。

## 契合度檢查

| 問題 | 證據 |
|---|---|
| 題目是否符合列出的領域？ | 領域說明的原文引述 |
| 貢獻類型是否符合會議接受的類型？ | 徵稿說明中的貢獻類型 |
| 證據是否達到會議要求的成熟度？ | 截止日前能完成確認階段（confirmatory）的結果，或只有篩選階段的結果 |
| 研究是否使用該會議社群預期的內容（例如多媒體會議預期使用媒體內容）？ | 可行性紀錄 |

通用案例：研究中的方法被發現完全不使用媒體內容之後，一個多媒體會議從備案清單中刪除。

## 備案

- 依序列出備案，每個都附真實日期，並在官方網頁上確認。
- 在某個會議審查中的論文，在結果通知之前不能投到其他地方。截止日早於該通知的備案，不能用於這篇論文。
- 同一專案的兩篇論文需要各自的範圍；檢查重複投稿規則中關於內容重疊的規定。

通用案例：一個後續研究規劃的備案，被發現與第一志願的截止期間相同，因此沒有提供第二次機會。

## 時程

從摘要截止日往回推：

| 項目 | 時間 |
|---|---|
| 方向的繼續或停止決定 | 留出確認階段執行與撰寫的時間 |
| 確認階段的執行 | 在撰寫凍結主張之前完成 |
| 審稿人角度的內部審查 | 摘要截止日之前，並留時間處理發現的問題 |
| 摘要登記 | 依徵稿說明的要求 |
| 全文與投稿檔案包 | 在編譯後的版本上檢查頁數上限 |
| 已在審查中論文的 rebuttal 期間 | 在時程中預先保留 |

投稿之後，已投稿的版本保持凍結：後續工作絕不改動已投稿的產出物、它的程式釋出版本或它的結果列。
