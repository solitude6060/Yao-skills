# 實驗卡、矩陣與追蹤表

英文版 [experiment-card.md](experiment-card.md) 為執行規範。

實驗卡是規劃的單位：一個問題、一個介入（intervention：唯一改變的那件事）、一個決定。矩陣列出研究需要的每個儲存格（cell）；追蹤表（tracker）顯示哪些儲存格已經存在。三者都放在專案既有的計畫檔或結果登記表中；不另建一套平行的文件系統。

## 實驗卡範本

讓專案外的讀者第一次讀就看得懂。每個內部標籤（使用者群名稱、變體代號）第一次出現時附簡短說明。

```text
實驗卡：              <簡短的描述性名稱，不用代號>
研究問題：            <它服務的研究問題，名稱與專案研究問題檔一致>
目的：                <現在不知道什麼，以及答案為什麼重要>
介入：                <被比較的各組之間唯一改變的那件事>
最接近的簡單對照：    <能產生同樣結果、成本最低的替代做法；與方法並排執行>
固定不變：            <資料版本、使用者群檔案、候選檔案、模型版本、讀出方式、seed>
母體與目標：          <由研究問題推導；領域規則來自負責評估協定的 skill>
輸入：                <資料、附雜湊值的使用者群檔案、附雜湊值的候選檔案、模型與版本、輸入格式>
輸出：                <逐單位結果檔、指標、成本欄位、位置>
證據階段：            screening（篩選） | confirmatory（確認）
預期判讀：            <相對於點名比較對象的方向>；推翻主張的結果：<什麼結果會否定主張>
失敗處理：            <執行失敗重跑到成功；方法失敗計入；重試輪數事先宣告>
成本：                <計畫單位數 ÷ 量測的每小時單位數 + 載入與排序時間、金額、裝置；量測前標為「估計」>
會改變的決定：        <結果 -> 下一步，每種結果各一>
狀態：                planned | running | executed | verified | admitted | superseded
```

預期判讀的通用例子：「在驗證使用者上，組合方法的排名高於單獨的凍結模型；若沒有，輔助訊號從方法中移除」。它寫出方向與比較對象，不寫「至少好 0.02」這類數值門檻。

## 規則與它們防止的失誤

| 規則 | 防止的失誤 |
|---|---|
| 每張卡寫明它服務的問題；沒有問題或沒有決定的卡刪除或合併。 | 在主張存在之前就收集、什麼都沒回答的實驗。 |
| 輸入與輸出寫清楚，包括方法的讀出方式（readout：從模型輸出取得分數的方法）與寫出的檔案。 | 之後沒有人能解讀或重現的結果。 |
| 預期判讀是相對於點名比較對象的方向，在執行前寫下。 | 知道結果之後才爭論關卡。 |
| 方法失敗的重試規則（輪數、解析器不變）是卡片的一部分，並保留重試前的分數。 | 看過分數之後才決定重試。 |
| 狀態在所有卡片、追蹤表與狀態報告中使用同一套固定詞彙。 | 標為「完成」的儲存格從未經過驗證或收錄。 |

## 矩陣與追蹤表

矩陣在協定確定時寫一次，是方法 × 資料集 × 條件 × 使用者群的組合（研究有變動候選集合大小或其他軸時，加上該軸）。追蹤表的欄位：

| 欄位 | 內容 |
|---|---|
| 方法 | 名稱與變體，變體說明一次 |
| 資料集、條件、使用者群 | 儲存格的座標 |
| 證據階段 | 篩選或確認 |
| 狀態 | planned 已規劃、running 執行中、executed 已執行、verified 已驗證、admitted 已收錄、superseded 已被取代 |
| 執行身分 | 執行識別碼或結果檔路徑 |
| 成本 | 量測的時間、記憶體、金額 |
| 實驗卡 | 該儲存格所屬的卡 |
| 備註 | 為什麼跳過某個儲存格，以及由誰決定 |

加上一個涵蓋檢視（coverage view）：方法為列、條件為欄，每格標為完成、待做，或附理由的跳過。它讓人一眼看出哪個方法跑了較大的條件卻沒跑較小的，或哪個模型大小在比較中缺席。寫任何比較之前，先檢查涵蓋檢視。

## 階梯

上一階產生可用的訊號之後才擴大：

| 軸 | 階梯 |
|---|---|
| 使用者 | 小型開發群，接著是報告群，再來是包含前面使用者的更大樣本 |
| 候選 | 小候選集合，接著是較大的集合，協定需要時再到完整商品目錄 |
| 模型 | 用一到兩個模型做出完整原型，接著是不同大小或訓練方式的變體，再來是閉源模型 |
| 資料集 | 開發用資料集，接著是事先承諾的其他資料集 |

比較的廣度與機制分析的深度各自編列預算：廣泛比較，只對結果有資訊價值的模型深入分析。

## 通用案例

- 一批實驗只有部分方法回報了較大候選數的結果；直到追蹤表列出哪個方法跳過哪個大小，這個比較才讀得懂。
- 一個較大模型的執行很晚才被發現缺漏，因為沒有涵蓋檢視。
- 實驗頁面列出結果，卻沒有目的、輸入或輸出；專案外的讀者看不出每個結果回答了什麼。
