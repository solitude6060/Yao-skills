# 使用者群與曝光紀錄

英文版 [cohorts-and-exposure.md](cohorts-and-exposure.md) 為執行規範。

使用者群（cohort）的名稱說不出它被用來做過什麼；它的曝光紀錄（exposure history）才說得出。在第一個結果出來之前規劃各群的角色，並把曝光紀錄和使用者群檔案放在一起。

## 角色

| 角色 | 用途 | 規則 |
|---|---|---|
| 開發 | 方法設計、變體比較、除錯 | 任何用途都可以；它的結果不支持任何泛化主張 |
| 選參或校準 | 在驗證目標上選係數、checkpoint（模型檢查點）或設定 | 只用驗證目標（這些目標可以屬於報告群的使用者，例如 leave-one-out（留一法：每位使用者最後一筆事件作測試目標）或全域時間切分；使用者互斥協定下則不可以）；選參規則在執行前寫好 |
| 報告 | 對凍結的設定在測試目標上評分一次 | 在第一個結果出來之前保留；絕不用來挑選變體；只有它的驗證目標可以用來選設定（例如逐使用者 leave-one-out 或全域時間切分）；使用者互斥協定下它的任何目標都不可以 |
| 確認 | 之後加入的使用者，用來檢查結果在未參與任何設計的使用者上是否成立 | 在設定凍結之後抽取；另外報告 |

每個使用者群寫成一份附雜湊值的識別碼檔案，加上抽取它的規則（例如固定 seed（隨機種子）的隨機抽樣）與它的角色。每個使用者群第一次出現時給一個中性的描述性名稱，並全程沿用。

## 擴大樣本

- 較大的樣本包含已經評估過的使用者，讓先前的結果仍是新結果的子集，研究只回報一個母體。新加入的使用者與開發用使用者分開回報。
- 基線的官方程式在一部分使用者樣本上選參時（有些序列推薦程式在大型資料集上固定抽取一定數量的使用者做驗證），讓每個基線讀取同一份樣本檔。協定允許選參讀取被評估使用者的驗證事件時（例如逐使用者 leave-one-out 或全域時間切分），樣本要包含被評估的使用者；研究問題需要未見過的使用者時（使用者互斥協定，user-disjoint），樣本要排除他們。
- 依階梯擴大，在決定所需的大小就停下；記錄每個結果使用的大小。

## 曝光紀錄

宣稱某個使用者群是保留群（held out）或全新的之前，列出先前與其目標的每一次接觸：

| 接觸 | 例子 |
|---|---|
| 方法設計 | 在這些使用者的測試目標上比較變體 |
| 選參 | 用他們的測試目標選係數或 checkpoint（協定允許時，例如逐使用者 leave-one-out，在他們的驗證目標上選參不算接觸；使用者互斥協定下則算接觸） |
| 分析 | 讀過他們目標的機制分析、案例研究、錯誤檢視 |
| 姊妹專案 | 另一個重用了相同使用者或目標的專案 |
| 先前的協定 | 在已被取代的切分下，把這些事件當作目標的執行 |

有任何接觸的使用者群，對那次接觸可能影響的主張而言就是開發資料。在論文的程序說明中寫明曝光情形；它屬於 `paper-writing` 的必留揭露清單（must-keep disclosure list）。

## 重複執行

寫明重複執行之間什麼會變、什麼固定：seed 會變；使用者、目標、候選、模型與方法固定。同時改變了測試集的重複執行，量測的是另一件事。

## 資料集的事先承諾

下載將加入比較的資料集之前，寫一份說明點名這些資料集，並聲明每個結果都會進入比較，然後記錄這份說明的雜湊值。之後只有在理由與其結果無關時，才能移除某個資料集。

## 通用案例

- 早期的協定允許在第一個使用者群的測試目標上選方法。後來的修訂把該群重新歸類為開發資料，並新增一個保留群與一個確認群。
- 一個後續專案的使用者群，與姊妹專案為其研究抽取的使用者重疊；曝光清查發現了重疊，這些使用者在任何結果出來之前就被移除。
- 一項「全新」的主張被撤回，因為每個被重用的測試目標都已經出現在先前的分析中。
- 一個較大的樣本最初在抽取時排除了已評估的使用者，這會讓回報的母體變成兩個獨立樣本的總和；後來重抽，讓它包含這些使用者。
