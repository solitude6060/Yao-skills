# 社群版同步計畫

## 目標與來源

依 Yao-Garyu research-toolkit 0.8.0 更新公開社群版，納入台灣版 wait-what，
並根據已核對的近期專案紀錄整理開發流程。Yao-Garyu 維護個人工作流程來源；
本版提供可移植的指引與範例。

來源基準為 Yao-Garyu `66d32ad13410e534370c95f156f84a5e41a3fd9f`，加上已推送的
wait-what 分支 `e7385d253e2befa6553508a9e34bc88a0dbe620e`。
社群版基準為 `ee0e5ae00e452a26d8b9972f3c4094094eff34f6`。
兩個遠端均於 2026-09-13 重新取得。wait-what 分支已在遠端，先前停在建立
pull request（合併請求）之前；本次先完成該整合，再記錄最終來源版本。

## 範圍與決定

- 與來源對齊：八個原創技能、karpathy-guidelines、wait-what。依來源 0.7.0
  移除十四個 OMC 複本，指向上游安裝方式，保留歷史授權紀錄。
- 同步雙語技能及必要支援檔案；保留授權、證據要求及 wait-what 明確呼叫設定。
- 將個人絕對路徑、私人事件與帳號／模型假設改成可設定的本機政策檔及匿名範例。
  不公開私人專案紀錄、憑證、執行環境備份或模型路由表。
- 更新兩份 README、套件資訊、授權及行為範本，涵蓋直接執行、計畫、回歸測試、
  有範圍的委派、獨立審查、專案記憶、最小研究證據及技能選擇。
- 保留既有未追蹤的 `.omc/`；本次社群版更新不修改使用者的執行環境設定。

## 順序與驗收

1. 先在功能分支提交本計畫。
2. 驗證並透過合併請求整合既有 wait-what 分支。
3. 同步社群內容，記錄可移植性調整。
4. 檢查技能清單、設定、翻譯、相對連結、授權、私人路徑、明確呼叫設定及空白差異。
5. 更新 status.md、tracker.md、handover.md 的交付證據，提交、推送並透過合併請求整合。

本次修改指引文件及套件資訊，未定義實驗指標或正式結果，也未新增可執行功能，
採文件驗證。若需修改可執行行為，先補對應失敗檢查，再套用程式碼審查要求。


## 面向讀者的 README 修訂

使用者要求 README 寫給初次認識專案的人。兩個語言版本改以用途、開始使用、
開發流程與技能選擇為主，移除交付稽核敘述、匿名化說明、內部模型／帳號設定
及執行環境維護指令，保留必要安裝方式及專用指南連結。本次為編輯修改，
技能及程式不變；檢查連結、雙語涵蓋與空白差異後透過文件合併請求交付。

確認範圍也包含 routing、first-principles 與 wait-what 的使用時機、依情境選用技能、
ponytail 與 i-have-adhd 的搭配方式，以及 Claude Code、Codex、Grok Build、Cursor、
Pi Agent 本體與本套技能的安裝。已完成雙語改寫，並核對官方來源、雙語涵蓋範圍、
本機連結、指令呈現及 Bash／zsh 安裝範例。
